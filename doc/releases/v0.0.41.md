## Abstract

YaGo v0.0.41 restores common-query search under concurrent ingest by validating each bounded Bleve candidate set in one document-vault snapshot. It upgrades Bleve to v2.6.1 and zapx to v17.2.3 behind a writer-generation transition, completes ADR-0063 post-open RWI filter maintenance, and pins fixed OpenSSL 3.5.8 packages. Image builds retry two transient Go module transport failures without disabling checksum authentication. The ADR-0063 post-gate cancellation guard now has deterministic exact coverage. Existing v0.0.38 data advances without a full-text rebuild; wire surfaces and deployment topology are unchanged. Rollback to v0.0.38 rebuilds the derived index. v0.0.39 and v0.0.40 were unpublished failed attempts and are not reusable.

## Changes

### Validate stored candidates in one snapshot

Disk search previously opened one document-vault transaction for every Bleve hit before hydrating the visible page. A common query could therefore perform 51 separate presence checks plus evidence reads while crawler ingest competed for the same storage boundary. The fixed 1.8-second interactive budget expired even though the Bleve query itself completed in tens of milliseconds.

The document directory now offers ordered set presence through one URL-boundary acquisition and one vault snapshot. The result remains aligned across present, missing, and duplicate URLs. Search uses that path only for the bounded stored-candidate set; full documents remain lazy, missing rows remain ordinary orphan candidates, and implementations without the optional projection retain their compatibility path. The existing exact-page hydration bound is unchanged.

### Advance the Bleve writer generation

The embedded backend now pins Bleve v2.6.1, zapx v17.2.3, and their selected companion APIs. Only the exact v0.0.38 corrected-writer generation is accepted as a compatible predecessor. Its mode-0600 generation marker advances to v2 before Scorch can write and avoids a document rebuild. A current marker is unchanged, a failed transition refuses startup, and missing, malformed, or unknown evidence retains the established rebuild-or-refuse path.

The boundary follows a disposable 12,000-document compatibility gate. The new reader preserved old logical totals through reopen. After update, delete, and forced merge under the new writer, the new stack reopened with the expected totals while the v0.0.38 dependency stack failed to open the new output. The generation transition therefore records a real one-way writer boundary rather than assuming rollback compatibility.

### Serve before optional RWI filter construction

ADR-0063 is now Accepted and implemented. Vault open installs one conservative RWI word filter per shard without scanning stored postings, so this optional accelerator cannot delay listeners or readiness. One owned maintenance worker builds one shard at a time through bbolt snapshots of at most 4,096 records and yields between pages when live reads or admitted writes need storage.

Concurrent term writes remain in the existing side set and a completed filter publishes only under the exclusive vault gate. Cancellation, collection or construction failure, and shutdown retain the conservative answer, which may seek extra shards but cannot hide a posting. Split and compaction schedule the same maintenance path. Close cancels and joins the worker before closing shard databases.

### Select fixed crawler runtime libraries

The pinned Alpine v3.24 crawler image explicitly installs `libcrypto3=3.5.8-r0` and `libssl3=3.5.8-r0`. This replaces the OpenSSL 3.5.7 revision inherited from the otherwise unchanged base image and clears CVE-2026-14456 from the release image inventory. Firefox ESR 140.12.0, the static crawler binary, non-root identity, entrypoint, and image name are unchanged.

### Bound authenticated module downloads

Both product Dockerfiles use one release-engineering boundary for `go mod download`. A failed operation is repeated at most twice after two- and four-second pauses. Each attempt uses the ordinary pinned module graph, proxy policy, and Go checksum-database authentication. First-attempt success performs no pause; a persistent proxy, checksum-service, checksum, or module failure still stops the native image job after the third attempt.

This corrects the transient transport failure that stopped the immutable v0.0.39 arm64 image build. It does not disable `GOSUMDB`, accept a checksum mismatch, add an alternate dependency, or make a failed architecture optional.

### Make post-gate cancellation evidence deterministic

Word-filter publication checks cancellation before and after acquiring the exclusive vault gate. The original post-gate test blocked the filter constructor and cancelled after a signal emitted before the real constructor returned. Runner timing could therefore select either cancellation check, making exact coverage nondeterministic even though both outcomes safely retained the conservative filter.

The test now uses the package's established cancellation-race context to select the post-gate check directly. It asserts the cancellation error and unchanged conservative filter, while ordinary maintenance tests continue to prove successful publication. The timing-only constructor hook is removed. This changes no runtime statement, lock, context, stored data, setting, or public behavior.

### Close the ADR implementation inventory

The release audit checked ADR-0000 through ADR-0064 against their status, runtime boundaries, and tests. ADR-0000 remains the proposal template; ADR-0007, ADR-0030, and ADR-0035 are explicitly Superseded. Every other live decision is Accepted. ADR-0063 was the sole queued implementation and is included in this release; no accepted implementation remains knowingly deferred.

- No environment variable, Admin setting, default, navigation item, shelf row, Prometheus series, systemd unit, Compose control, or runtime service boundary changes.

- Conservative RWI filters preserve results while background optimization is incomplete. They change only shard-skip performance and are neither authoritative storage nor the local full-text engine.
- DDGS provider policy remains admin-opt-in. This release does not enable, disable, or replace an operator's stored fallback mode.
- Module-download retry exists only while constructing product images. It does not change either runtime binary, package installation, trust roots, or outbound runtime behavior.
- The deterministic coverage correction changes test control only. Runtime output from the v0.0.40 source commit is otherwise unchanged.
- The crawler container changes two Alpine package revisions only. Bare-metal Debian, RPM, and tarball crawler runtimes continue to use host trust roots and browser facilities as documented.

## Upgrade and rollback

1. After the immutable tag workflow succeeds, download the architecture-matching v0.0.41 Debian package. Verify its GitHub artifact attestation against repository `D4rk4/yago`, workflow `.github/workflows/release.yml`, tag ref `refs/tags/v0.0.41`, and the tagged source commit before stopping either service.
2. Follow the target's data-protection policy. Generic bare-metal nodes take one coordinated stopped backup. The documented `root@yagoseek.dev` exception preserves every existing archive under `/opt/yago/backups` and creates no new pre-upgrade backup; stage the verified package under `/opt/yago/releases`.
3. Stop `yago-crawler` and `yago-node`. Install the package with `dpkg -i` and confirm that package installation did not start either service automatically.
4. Start `yago-node` first. A healthy v0.0.38 index should advance its generation without a full-text rebuild, and optional RWI filter maintenance should continue after listeners open. Wait for health, readiness, exact version, common-query search probes, and bounded logs before starting the crawler.
5. Start `yago-crawler`, confirm v0.0.41 and a newly accepted logical session, then verify crawl progress, index growth, DDGS behavior under the stored operator policy, service restart counts, and absence of a repeating lease-loss loop.

For rollback to v0.0.38, stop both services, install the exact older package, and leave the v2 generation evidence intact. v0.0.38 treats it as unknown and rebuilds the derived Bleve index from stored documents before opening it. Reserve enough free space and maintenance time for that complete rebuild, then start the node before the crawler.

A v0.0.35 or earlier node has no compatible generation admission and must not open v2.6.1-written output. Restore a compatible coordinated stopped backup, or move `search.bleve`, `search.bleve.segment-generation`, and `search.bleve.rebuild-required` together to an operator-chosen quarantine outside the active data root before starting the older node. It will reconstruct the missing derived index from stored documents. Retain the quarantine until rollback is verified; never copy or relabel a generation file to make unlike writers appear compatible.

## Known limitations

- Post-open RWI filter maintenance can still read the complete RWI keyspace, consume storage bandwidth and file cache, and make RWI scans seek every shard until each filter is ready. It yields at page boundaries and no longer determines HTTP availability, but it is not persistent or a zero-I/O startup mechanism.
- The one-snapshot candidate path is locally and synthetically verified; its effect on the previously failing production queries remains to be confirmed after deployment of the published package.
- Bleve v2.6.1 and zapx v17.2.3 correct the known empty-middle-chunk writer class. They do not add a general decoder allocation bound for arbitrary current-generation corruption; that remains upstream work in `blevesearch/bleve#2393`.
- DDGS engines are external and can throttle, change markup, or return an honest empty result. Fallback remains disabled unless an administrator explicitly enables the applicable mode, and this release does not alter the stored production policy.
- Bounded retry tolerates no more than two transient module-download failures. A longer proxy, checksum-service, or network outage still fails the release workflow by design.
- Rollback to v0.0.38 incurs a complete derived-index rebuild. Rollback to v0.0.35 or earlier requires a compatible stopped backup or quarantine of the new derived index and both sibling state files.
- Issue #3 remains open because a point-in-time resident-memory value does not establish growth or pressure. Use the existing Admin memory split together with cgroup events and repeated observations before attributing file-backed residency or anonymous memory.
