## Abstract

YaGo v0.0.38 makes crawler availability explicit on the Admin Crawler page. The live monitor now reports Connected, Disconnected, or Unavailable in text, includes the connected-process count, and explains that queued orders remain pending when no crawler is connected. This addresses the operator-visibility gap found when the enabled production crawler unit was inactive while durable work continued to queue. The release also updates the existing e2e-only archive dependency beyond CVE-2026-17106 and records a deferred design for serving before RWI word-filter reconstruction. No crawler start policy, runtime dependency, protocol, setting, storage format, port, service topology, or deployment control changes. Upgrade and rollback require no data conversion.

## Changes

### Expose crawler connection state

The existing five-second Crawler monitor fragment now reads the bounded typed crawler activity source and renders one of three states. Connected includes the current process count. Disconnected states that no crawler is connected and that queued crawl orders remain pending until one connects. Unavailable distinguishes missing or invalid telemetry from a confirmed zero-worker state.

The state is written explicitly and accompanied by an existing Carbon-token tag, so color is not the only status carrier. The same server-rendered fragment works with periodic htmx refreshes and without JavaScript. It adds no shelf row, navigation item, request-time storage scan, unstable JSON dependency, route, listener, or setting.

### Remove a vulnerable e2e dependency version

The node and crawler e2e modules now pin `github.com/moby/go-archive` v0.3.3 instead of v0.2.0. The earlier version is affected by CVE-2026-17106, in which crafted archive links can escape the intended extraction directory. This dependency is used by Testcontainers in the test harness; it is not linked into either product binary. The upgrade also resolves its pinned `klauspost/compress`, `moby/sys/sequential`, and `moby/sys/user` versions.

### Record bounded follow-up work

ADR-0063 records a future design that opens runtime listeners before reconstructing RWI word filters and fails only RWI-dependent paths while reconstruction is incomplete. It deliberately makes no runtime change in this release. Workspace instructions now also require explicit control flow, state ownership, narrow typed boundaries, and refactoring before orchestration becomes tangled.

## Upgrade and rollback

1. After the immutable tag workflow succeeds, download the architecture-matching v0.0.38 Debian package. Verify its GitHub artifact attestation against repository `D4rk4/yago`, workflow `.github/workflows/release.yml`, tag ref `refs/tags/v0.0.38`, and the tagged source commit before stopping either service.
2. Follow the target's data-protection policy. Generic bare-metal nodes take one coordinated stopped backup. The documented `root@yagoseek.dev` exception preserves every existing archive under `/opt/yago/backups` and creates no new pre-upgrade backup; stage the verified package under `/opt/yago/releases`.
3. Stop `yago-crawler` and `yago-node`. Install the package with `dpkg -i` and confirm that package installation did not start either service automatically.
4. Start `yago-node` first and wait for health, readiness, exact version, and search probes. Start `yago-crawler` next, confirm v0.0.38 and a newly accepted logical session, then verify that the Crawler page reports Connected and that crawl work advances the index.

For rollback, stop crawler and node and reinstall v0.0.37. No data restore, format conversion, setting migration, or service-unit change is required solely for this release. After restarting node and then crawler, verify readiness, exact v0.0.37 identities, crawler connection, queue progress, and search responses.

## Known limitations

- An enabled systemd crawler unit can still be inactive. This release makes that state visible; it does not add a second supervisor, change systemd start policy, or start a crawler from the node.
- The production crawler showed short recoverable heartbeat and progress RPC deadline clusters under load. They did not cause a work-stream reconnect, a new session, a restart, repeating lease loss, or stalled indexing, but their latency source remains unconfirmed.
- RWI word-filter reconstruction remains a pre-listener startup operation. ADR-0063 describes the intended bounded recovery model, but no serve-before-reconstruction behavior is implemented here.
- The Crawler monitor reports process connections known to the current node runtime. It does not prove that every connected process can reach every external target or that every fetched page will pass robots, transport, parsing, or content-quality admission.
- The exact 4 GiB Docker gate covers the bounded test corpus. A large mapped vault can show high file-backed RSS; RSS alone is not evidence of a heap leak or unreclaimable memory pressure.
