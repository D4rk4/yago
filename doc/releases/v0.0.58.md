## Abstract

Yago v0.0.58 prevents selective multi-term searches from exhausting the interactive deadline before returning local rows. Disk retrieval formerly admitted the union of positive terms, so one common term could force an exhaustive analyzer-scoped read. Candidate selection now follows complete lexical requirements, while the unchanged final query remains authoritative. The outer deadline preserves an already queued result. The release gate adds pinned security and nil-flow analysis, reusable API compatibility, reachable-vulnerability checks, shuffled tests, active fuzz smoke, and explicit race tests. Public artifacts replace copied operational input with neutral evidence. The cancelled v0.0.57 tag remains immutable attempt history. Runtime APIs, formats, settings, runtime dependencies, and topology are unchanged. No migration or index rebuild is required.

## Changes

### Bound multi-term reads by complete lexical requirements

An anonymous production two-term request could return an incomplete zero-row page on its first read and local rows on an immediate repeat. Fresh longer variants reproduced the first-read failure at the 1.8-second response deadline. The node stayed ready, both services kept zero restarts, and their cgroups recorded no high, max, or OOM event.

The disk candidate query previously formed the disjunction of every individual positive term across eligible analyzers. That was complete but unnecessarily broad: one common term could reach the 4,097th per-child sentinel and select the exhaustive analyzer-scoped final query even when the complete multi-term requirement was selective. On an isolated copy of the production Bleve tree, that union admitted 1,786 candidates for the reported request; the complete lexical requirements admitted seven and retained the same five final hits. Two longer reproduced variants fell from 51,703 and 45,683 union candidates to zero exact candidates with unchanged zero exact totals.

The candidate query is now a disjunction of complete analyzer-specific lexical requirement branches. Strict and fuzzy branches require every retained term. Relaxed branches apply the same minimum-term rule as the final query. Stopword removal stays local to each analyzer branch, whole-query analyzer equivalents share the standard branch, and independently variable dictionary branches remain distinct. Exclusions, domain constraints, expansion terms, analyzer scope, scoring, ordering, and pagination remain owned by the unchanged authoritative final query.

The existing same-reader boundary and conservative overflow rule remain intact. Each child inspects at most 4,097 candidate identities. A complete set of at most 4,096 becomes the internal zero-score filter; the sentinel becomes MatchAll and retains exhaustive retrieval without truncation. Explicit explanations remain exhaustive. Dead per-term analyzer-coalescing code was removed instead of retaining an unused second abstraction.

At the outer hard deadline, the node now performs one nonblocking receive before synthesizing a timeout. A pipeline result that is already queued is returned; unfinished work receives no extra time. Permanent tests prove both outcomes, alongside strict, fuzzy, relaxed, analyzer-stopword, legacy-mapping, and unavailable-mapping candidate behavior. The existing optimized-versus-exhaustive suite continues to prove exact result identity, order, score, total, status, filters, expansion scoring, and honest empty answers.

ADR-0078 records the requirement-aware candidate and queued-completion boundary and amends ADR-0070 and ADR-0072. FTR-203 records the implemented behavior and synchronizes the affected historical feature entries. The release audit matched all 84 numbered ADR files to 84 unique index targets: 80 live decisions are Accepted, ADR-0007, ADR-0030, and ADR-0035 are Superseded, and ADR-0000 is the non-decision template. ADR-0071 explicitly leaves a replicated read runtime to a future service-boundary ADR; no accepted or queued ADR implementation remains knowingly outstanding.

An isolated four-processor backend diagnostic ran the corrected request against the copied production Bleve corpus. The first read completed in 45.871 milliseconds. All 100 synchronized, queue-inclusive reads returned hits inside their 1.8-second contexts: p50 399.922 milliseconds, p95 697.445 milliseconds, p99 732.995 milliseconds, and maximum 733.132 milliseconds. This is evidence for the changed candidate and read boundary on that host and copy, not a full HTTP or production-capacity claim.

## Known limitations

- The copied production diagnostic contains the Bleve tree but not the document vault. It validates candidate selection and native read behavior, not result projection, the complete HTTP path, or the production host's cold storage latency.
- One four-processor process is not validated for hundreds of complete HTTP requests with projection, evidence, peer work, provider work, and response encoding. Sustained hundreds-request service needs separately implemented and measured horizontal read capacity with independent CPU and I/O, independently owned immutable generations, query-ready projections, freshness-aware routing, queue-inclusive admission, and one-replica-loss capacity. Multiple processes must not share one live mutable Scorch directory.
- DDGS fallback remains disabled unless an administrator enables the applicable mode. In explicit mode, an anonymous portal request does not provide fallback consent. This release does not bypass, reset, or infer the stored Admin policy.
- External engines can throttle, change markup, or return an honest empty result. The requirement-aware local candidate boundary does not make external providers part of local search correctness.
- Issue #3 remains open because a point-in-time resident-memory value does not establish growth or pressure. Use the existing Admin memory split together with cgroup events and repeated observations before attributing file-backed residency or anonymous memory.
- Gosec and NilAway are approximate static analyzers and cannot prove security or nil safety. The exact NilAway baseline initially retains 82 findings as review debt. Apidiff cannot detect behavioral compatibility, and govulncheck is limited by static reachability and the curated database. One shuffled order and a five-second fuzz smoke do not replace broader order exploration or sustained fuzzing. The race detector reports only races reached by executed paths and observed interleavings. Every gate remains complementary to review, exact coverage, lifecycle tests, Semgrep, Trivy, and production observation.
