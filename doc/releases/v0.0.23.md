## Abstract

YaGo v0.0.23 makes web-discovery crawl seeding operable without a node restart and stops it re-crawling pages the index already holds. The console switch, crawl depth, and page cap now apply live: enabling seeding starts publishing on the next search, and narrowing either bound applies to the next seeded order. Previously the seeder was wired once at startup from the boot value, so enabling it in the console changed nothing in the running process. Surfaced URLs are now rendered in the crawl contract's canonical spelling shared with the crawler, so an already indexed page is no longer re-seeded as a fresh domain crawl. Startup reports whether seeding can run. Defaults, environment variables, routes, listeners, and deployment topology are unchanged.

## Changes

### Live web-discovery seeding control

- The web-fallback crawl seeder is now wired whenever the node has a crawl order queue, and `web.fallback.seed_crawl` gates it at request time. Enabling web-discovery crawling in Admin → Configuration → Crawler therefore begins publishing crawl orders on the next search instead of taking effect only after the next node restart.
- Previously the seeder was installed once while the public search chain was assembled, under the boot value of that setting. A console change stored the override and left the running process unchanged, and the setting carried no live-apply hook, so an operator who enabled seeding and did not restart observed the fallback answering searches while nothing was ever queued for crawling.
- `web.fallback.seed_depth` and `web.fallback.seed_max_pages` are now resolved for each publication rather than captured when the seeder is built. Narrowing either bound applies to the very next seeded order, which lets an operator relieve a saturated crawl fleet without restarting the node. The swarm greedy-learning equivalents remain restart-only and are unchanged.
- The live switch closes at seed-URL admission, not only at publication. A silenced seeder therefore admits no URL into the bounded 128-job warming queue and emits no saturation warning for work it would then discard.
- Environment defaults are unchanged: `YAGO_WEB_FALLBACK_SEED_CRAWL` still defaults to `false`, and the shipped deployment examples still set it to `false`. Stored overrides continue to apply at startup exactly as before.

### Shared crawl URL canonicalization

- The canonicalization rules that decide one spelling of one page moved from the crawler's internal URL package into the crawl contract as `yagocrawlcontract.CanonicalURL`, and the crawler's `weburl.Normalize` now delegates to it. The node and the crawler can no longer disagree about a URL's spelling.
- The web-fallback seeder applies those rules before its stored-document presence check and before per-URL coalescing. It previously removed only the fragment, so the check missed for every result whose stored spelling differed — a home page surfaced as `https://host` against the stored `https://host/`, or any tracking-parameter variant — and an already indexed page was re-seeded as a fresh domain crawl on every repeat query while the publication idempotency key stopped coalescing those variants.
- The seeder's own admission rules are retained and applied after canonicalization: relative, credential-bearing, addressless, non-HTTP, and oversized identities are still rejected.

### Seeding observability

- Startup logs `web-search crawl seeding wiring` stating whether seeding can run and, when it cannot, whether the missing crawl queue or the disabled setting is the blocking condition. The seeding path previously logged only on failure or saturation, so a switched-off seeder and a healthy idle one were indistinguishable from outside the process.
- The seeding failure warning now carries the seeded URL. It previously carried only the profile name, which is the constant `web-fallback-seed` and attributed nothing.
- A successful publication is logged at DEBUG with the URL and whether the durable queue coalesced it into work that was already pending or leased.
- The search-explanation chain assembles its own copy of the retrieval chain; it neither seeds nor reports seeding wiring, so the startup report is emitted once and describes the live serving path.

### Regression coverage

- New tests cover the live switch in both directions through both seeder methods, the boot-configuration fallback when an assembly carries no runtime toggles, live narrowing of the depth and page cap on the next order including the derived whole-run budget, the three console hooks applying live, canonicalization of host case, default ports, tracking parameters, and dot segments, rejection of unseedable identities, and a stored page surfaced under a different spelling not being re-seeded.
- The crawl contract gains its own canonicalization suite covering the crawler's existing equivalence, tracking-parameter, session-token, unparsable-query, and session-variant-collapse cases, extended with the spellings the shared function must refuse. The crawler retains its equivalent suite against `weburl.Normalize`, so the delegation is proved from both sides.

## Compatibility

- No environment variable, route, request field, response field, public schema, listener, port, service, image name, package path, Bleve mapping, document encoding, or deployment topology changes. No dependency changes.
- The three web-discovery settings keep their keys, names, validation, and stored values. They change only from restart-required to live; the console no longer marks them as pending a restart. Stored overrides written by v0.0.22 apply unchanged.
- Seeding remains off by default. A node whose operator had already enabled `web.fallback.seed_crawl` and restarted behaves as before, except that already indexed pages stop being re-seeded.
- The crawler RPC and JSON contracts, the crawl-order shape, and the seeded profile shape are unchanged. `weburl.Normalize` keeps its signature and its results; only its implementation location moved.
- Canonicalization changes the spelling used as the publication idempotency key. An automatic-discovery order queued by v0.0.22 under a non-canonical spelling does not coalesce with the canonical spelling of the same page until it settles, so one page can hold two outstanding orders once across the upgrade. Both settle normally and no operator action is required.

## Upgrade and rollback

1. After the immutable tag workflow succeeds, download the architecture-matching v0.0.23 Debian package. Verify its GitHub artifact attestation against repository `D4rk4/yago`, workflow `.github/workflows/release.yml`, tag ref `refs/tags/v0.0.23`, and the tagged source commit before stopping either service.
2. Follow the target's data-protection policy. Generic bare-metal nodes take one coordinated stopped backup. The documented `root@yagoseek.dev` exception preserves every existing archive under `/opt/yago/backups` and creates no new pre-upgrade backup; stage the verified package under `/opt/yago/releases`.
3. Stop `yago-crawler` and then `yago-node`. Install the package with `dpkg -i` and confirm that package installation did not start either service automatically.
4. Start `yago-node` first. Verify the exact version, `/health`, `/ready`, configured listeners, and the `web-search crawl seeding wiring` startup line, which now states whether web-discovery seeding is active on this node.
5. Start `yago-crawler` after node readiness. Verify its exact version, control and ingest connections, a current heartbeat, and absence of repeating lease-loss output.
6. Keep production verification observation-only. Exercise seeding, restart, and materialization scenarios in the current-source local Docker gate rather than against the production node.

For rollback, stop crawler and node, reinstall the v0.0.22 package, start and verify the node, and then start the crawler. No index rebuild or data restore is required. The older node reads the same stored settings, but it resumes deciding seeding once at startup, so a console change again requires a restart, and it resumes seeding non-canonical spellings. Orders queued by v0.0.23 under canonical spellings remain valid and processable.

## Known limitations

- Web-discovery seeding remains off by default, and its depth and page-cap defaults are unchanged at 5 and 250. One fallback query surfaces up to `YAGO_WEB_FALLBACK_MAX_RESULTS` URLs and therefore queues that many whole-domain tasks; an operator enabling seeding should size both bounds against the crawl fleet's page budget, which is governed by the separate and also live `crawler.max_pages_per_second`, `crawler.fetch_workers`, and `crawler.run_pages_per_minute` controls.
- The live switch changes when seeding decisions are read, not what they cost. A backlog already queued under wider bounds keeps its own bounds; narrowing applies only to orders published afterwards.
- The swarm greedy-learning depth and page cap remain restart-required, as do the remaining web-fallback settings such as privacy mode and backend selection.
- Canonicalization repairs the seeder's presence check. It does not change what the crawler already stored, so pages indexed before this release under a non-canonical spelling remain under that spelling until they are recrawled.
- Successful ingest is not proof of a searchable page. The ingest content-quality gate remains enabled by default, rejects a page below its thresholds before storage, acknowledges it, and logs that rejection only at DEBUG, so the crawler still counts such a page as indexed. The `crawl_ingest_low_quality_total` counter remains the authoritative signal.
- An automatic-discovery order whose crawler lease is never settled still retains its URL identity until that lease settles, so that specific URL is not re-seeded meanwhile. This release does not add a lease-abandonment deadline.
