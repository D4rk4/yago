## Abstract

Yago v0.0.72 reduces node CPU spent outside search and stops a blocked web engine from consuming the web budget. It supersedes the unpublished v0.0.70 and v0.0.71 attempts. Ranking now reads per-field Bleve scores without building Bleve's diagnostic explanation text. The full-corpus signal pass now rests ten minutes or nine times its last scan time, whichever is longer. Any web engine that answers with a status other than 200, or with a page that yields no results, is paused with the existing backoff. The crawler image pins libexpat 2.10.0-r0. No setting, environment variable, listener, message shape or dependency changes; node and crawler may be upgraded in either order. On RPM 6 hosts, install the package with `dnf install`.

## Changes

### Pause every web engine that serves no results page

When the operator enables the web-search fallback, the node races several web engines. Only HTTP 202 and 429 paused an engine. An engine that served a captcha or challenge page with HTTP 200 to a blocked address was therefore asked again on every query, and its empty page reset its own pause. With the other engines paused, the web source repeatedly spent its budget on that engine, and searches that depended on it ended with HTTP 409.

The rule is now the same for every engine. Any status other than 200, or a 200 page that parses to no results, pauses that engine for 30 seconds, doubling up to 15 minutes. A page with results ends the pause. Transport and read failures remain backend errors. A race in which every engine refused reports the web source unavailable. The Tavily response shape and the HTTP 409 availability rule are unchanged.

### Crawler image libexpat baseline

The crawler image pins `libexpat=2.10.0-r0`, replacing `2.9.0-r0`, against which pinned Trivy 0.72.0 reports two HIGH advisories (CVE-2026-117610 and CVE-2026-118370). Both Alpine 3.24 architectures publish the new version. No runtime, configuration or wire change.

### Ranking field scores without diagnostic explanations

Lexical reranking, learned ranking and result reasons use per-field scores for title, headings, anchors, body, URL and analyzer fields. Bleve exposes those scores only through its diagnostic score explanation, so every field-score search asked Bleve to format that explanation for each matched document and each matched term. In a production CPU profile this formatting took about a fifth of search CPU.

A field-score search now scores each field leaf without the diagnostic text and attaches one precomputed per-field contribution to each match. Retrieval scores and result order are unchanged. Outside fuzzy recovery, the per-field scores equal those read from the full explanation. A search that asks for an explanation, including the explain endpoint, still receives the full diagnostic text. On a local 4,000-document benchmark, allocations per field-score search fell from about 2.38 million to 1.28 million, and its time matched a search without field scores.

### Corpus-signal pass rests in proportion to its scan time

The node refreshes authority, spelling, morphology and host-link signals with a pass over the whole stored corpus. Each pass started again ten minutes after the previous one finished, so on a large corpus a multi-minute scan took a large share of node CPU from search. The next pass now waits ten minutes or nine times the last scan time, whichever is longer, so the pass uses at most a tenth of wall time. A restored checkpoint still delays the first pass only until its recorded due time.

### RPM upgrade smoke under RPM 6 signature enforcement

The v0.0.70 attempt stopped in the amd64 RPM smoke test. The test installs the package with `dnf`, then reinstalls it with `rpm -U --replacepkgs` to exercise the upgrade migration. The floating `fedora:latest` image now provides Fedora 45 with RPM 6.1, which requires an OpenPGP signature for `rpm -U` by default. The release package carries none; its integrity comes from the GitHub artifact attestation. The test now reinstalls with `--nosignature`. The package contents, scriptlets and attestations are unchanged. The deployment guide now states that operators install with `dnf install`, or with `rpm --nosignature` after verifying the attestation.

### Bound module downloads in the release binary build

The v0.0.71 attempt stopped in the amd64 binary build when the Go module proxy reset one download stream during `go build`. The release build job now downloads modules through the same bounded downloader that both product Dockerfiles use before it builds. A failed download is attempted at most three times with two- and four-second pauses, checksum verification stays enabled on every attempt, and an exhausted downloader still fails the job. The binaries, packages and images are unchanged.

## Compatibility

- No YaCy, Tavily or node-crawler message shape or status code changes.
- Node and crawler from this release interoperate with the v0.0.69 node and crawler; they may be upgraded in either order.
- Explain requests return the same diagnostic text as before. Fuzzy recovery searches report one field-score contribution per field instead of one per matched spelling variant.
- Corpus signals on a large corpus refresh less often than before; a corpus whose pass takes under about 67 seconds keeps the ten-minute cadence.
- No setting, environment variable, listener, service, image repository or new dependency is added.
- The reusable-module API gate compares against the exact previous published v0.0.69 tag and source commit; the unpublished v0.0.70 and v0.0.71 attempts are not consumer baselines.
- On RPM 6 systems, `rpm -i` and `rpm -U` of the unsigned package need `--nosignature`; `dnf install` of the local file works without it.

## Upgrade and rollback

Verify the published package's GitHub-hosted attestation against repository `D4rk4/yago`, the exact release workflow, tag ref and source commit. Use matching node and crawler binaries. Preserve configuration and data; ordinary deployments should use the established stopped-service backup procedure. Where an explicit target-specific operator policy omits a new pre-upgrade backup, preserve every existing archive unchanged.

Stop the crawler and node, install the published package, then start and verify the node before starting the crawler. The package enables the units but does not start them automatically. Web engine pauses and corpus-signal timing are held in memory and start fresh after a restart.

Rollback reinstalls the previous verified matching package with both services stopped. No stored data format changes, so rollback needs no data conversion.

## Known limitations

- Fuzzy recovery searches attribute one score per field instead of one per matched spelling variant, so their per-field scores can differ from the full explanation.
- Opening Bleve term readers across index segments remains the largest search CPU cost; this release does not change it.
- Bug #3 (node memory use) remains open; this release does not change memory behavior.
