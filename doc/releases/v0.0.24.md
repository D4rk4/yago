## Abstract

YaGo v0.0.24 makes automatic crawl discovery honest and bounded. A recrawl is re-dispatched under the priority it was first crawled with, so a seeded page no longer inherits the operator whole-run budget. A page the ingest quality gate refuses is reported to the crawler and counted as fetched, not indexed. An expired lease whose worker never returns is reclaimed after a deadline instead of pinning its URL forever. Seed depth and page caps default to values sized against the crawl fleet, and every automatic-discovery control applies live. The console states which settings need a restart. The fetch governors, refused pages, and failed schedule writes are now measurable. `IngestAck` gains two additive fields; node and crawler of either version interoperate.

## Changes

### Recrawl keeps its crawl-order priority

- The recrawl sweeper re-dispatches a due URL under the priority its profile was first dispatched with, and the durable recrawl profile record now carries that priority. It previously rebuilt the order from the profile alone, so every recrawl left the queue as an ordinary operator order.
- An automatic-discovery order's whole-run page budget is bounded by its per-host cap; an ordinary order's is not. A recrawled web-discovery or swarm-seed URL therefore lost that bound, and a profile persisted before seeded orders carried an explicit whole-run cap resolved instead to the crawler bootstrap default of 50,000 pages. One due page could expand into a domain-scoped depth-5 crawl two orders of magnitude larger than its seed profile allows. The crawl monitor showed the symptom directly, as running `web-fallback-seed` and `swarm-seed` tasks whose whole-run maximum was 50,000 rather than their per-host cap.
- Manual crawls are unaffected and still derive no whole-run bound from their per-host cap. The stored profile record embeds the profile, so records written before this field decode unchanged and keep the ordinary priority they already had. The ingest backfill that fills a gap left by a failed profile registration still records no priority and never overwrites an existing record, so the next dispatch restores the authoritative value.

### Refused pages are counted honestly

- A page the ingest content-quality gate refuses is no longer acknowledged like a stored one. The node reports the refusal and the violated rule on the ingest ack, and logs it at INFO instead of DEBUG.
- The crawler records such a page as fetched, not indexed, and names the gate rule in the run's per-URL outcome. Previously the refusal was acknowledged as success, so `outcome.Indexed` counted it and the URL was classified as indexed: every total derived from a run tally, including the crawl monitor's indexed column, overstated the corpus.
- A refusal is an outcome, not a transport failure. It is not retried and does not count as a failed fetch.

### Abandoned leases are reclaimed

- An expired lease that still names a worker session is reclaimed once it passes an abandonment deadline of eight lease TTLs, in a pass deliberately disjoint from the ordinary expiry sweep, so checkpoint affinity keeps its exact meaning for every lease inside the deadline.
- Only worker-session adoption could previously release such a lease, and the worker id it needs lives in the crawler's frontier database. A crawler whose data directory was lost — a container recreated without a persistent volume — returned under a new id, could never adopt, and left the order leased forever; an automatic-discovery order also kept its URL identity, so that URL could never be seeded again. There was no deadline, no log, and no metric.
- The reclaim is derived from the lease TTL, so a longer TTL lengthens the grace period, and it logs a warning naming how many leases it reclaimed.

### Automatic discovery is sized against the fleet and applies live

- Web-discovery and swarm greedy-learning seed profiles both default to depth 1 with a 25-page cap, replacing depth 5 with 250 pages. Every surfaced result seeds its own whole-domain task, so the pages one query queues are the cap times the result count: the former defaults made a single fallback query worth 2,500 pages against a fleet whose page rate is governed in the tens per second.
- All six automatic-discovery controls — each path's on/off switch, crawl depth, and page cap — apply live. Both seeders are wired whenever the node has a crawl order queue and gated at seed-URL admission, so a silenced seeder occupies no warming-queue slot and emits no saturation warning for work it would discard.
- The process-wide warming queue is sized to hold four complete answers of `YAGO_WEB_FALLBACK_MAX_RESULTS` URLs, rather than a constant unrelated to the result count.
- Environment defaults are unchanged in kind: seeding stays off until an operator enables it, and a deployment that pinned the previous depth and page cap keeps them.

### Operability

- Admin → Configuration marks every setting as applying live or needing a restart before it is changed. The flag was already computed and passed to the page but never rendered, so an operator learned a setting was restart-only only after saving it. 73 of 114 settings are restart-only.
- The public result-window lifetime is an operator setting, `YAGO_SEARCH_SESSION_TTL` / `search.session.ttl`, applying live and bounded to 30 seconds through one hour.
- New crawler metrics `yacy_crawler_fetch_admission_waiting` and `yacy_crawler_fetch_admission_seconds` measure the wait on the fleet fetch-start permit and the process page-rate budget. A job waiting on either is still counted in `yacy_crawler_jobs_active`, so that gauge alone could not distinguish a busy crawl from a throttled one.
- New node counter `crawl_ingest_schedule_failures_total` counts stored pages whose durable crawl profile or recrawl entry could not be written, so the resulting refresh gap is alertable rather than only logged.
- A duplicate URL inside one extract request resolves once while still producing its own response row and consuming its own response budget.

### Test-layer corrections

- The crawl-order heartbeat request timeout is snapshotted when the receiver is constructed rather than re-read on every beat, so the receiver's heartbeat goroutine no longer reads a package variable that tests mutate and restore.
- The crawl-broker scripted clock installs its function once for the package run and guards the time it reports. The broker's lease-sweep goroutine calls that clock on its own schedule and is only asked to stop asynchronously, so it could still be running when a later test installed or released a clock. Four broker-starting tests now stop their broker.
- A bounded-recovery test gives each iteration a fresh admission, because the previous iteration's inner search outlives its budget and holds its slot.

## Compatibility

- `IngestAck` gains additive `rejected` and `rejection_rule` fields. Both default to the stored outcome, so a v0.0.23 node talking to a v0.0.24 crawler, and the reverse, keep their previous behaviour: an unflagged acknowledgement still means the page was stored.
- The recrawl profile record embeds the crawl profile, so its JSON stays a superset of what v0.0.23 wrote. Existing records decode unchanged with the ordinary priority they already carried, and are rewritten with the authoritative priority on the next dispatch under that handle.
- Automatic-discovery seed defaults change for deployments that never set them: depth 5 to 1 and 250 pages to 25. This reduces queued crawl work; a deployment that set either value explicitly is unaffected. The shipped `.env.example`, Compose example, and systemd environment example carry the new values.
- New environment variable `YAGO_SEARCH_SESSION_TTL` (default `5m`). No other environment variable, route, request field, response field, public schema, listener, port, service, image name, package path, Bleve mapping, or document encoding changes. No dependency changes.
- The six automatic-discovery settings keep their keys, names, validation, and stored values; they change only from restart-required to live. The 500-row public result horizon remains a retrieval invariant rather than a setting, and `MaximumHeartbeatActiveLeases` remains a wire bound both processes validate against.
- A crawl run that started before this release keeps the whole-run budget it was given, because a run's budget is fixed when the run starts. Runs already active under an inflated budget continue until they finish or are cancelled.

## Upgrade and rollback

1. After the immutable tag workflow succeeds, download the architecture-matching v0.0.24 Debian package. Verify its GitHub artifact attestation against repository `D4rk4/yago`, workflow `.github/workflows/release.yml`, tag ref `refs/tags/v0.0.24`, and the tagged source commit before stopping either service.
2. Follow the target's data-protection policy. Generic bare-metal nodes take one coordinated stopped backup. The documented `root@yagoseek.dev` exception preserves every existing archive under `/opt/yago/backups` and creates no new pre-upgrade backup; stage the verified package under `/opt/yago/releases`.
3. Stop `yago-crawler` and then `yago-node`. Install the package with `dpkg -i` and confirm that package installation did not start either service automatically.
4. Start `yago-node` first. Verify the exact version, `/health`, `/ready`, configured listeners, and the `web-search crawl seeding wiring` startup line.
5. Start `yago-crawler` after node readiness. Verify its exact version, control and ingest connections, and a current heartbeat.
6. Review any crawl run whose whole-run maximum exceeds its per-host cap in the crawl monitor. Those runs were dispatched before this release and keep their inflated budget; cancel them through the existing crawl control if their size is unwanted.
7. Keep production verification observation-only.

For rollback, stop crawler and node, reinstall the v0.0.23 package, start and verify the node, and then start the crawler. No index rebuild or data restore is required. The older node ignores the recrawl priority it does not read, so recrawls again lose it; it resumes acknowledging refused pages as stored, so indexed totals again include them; and it resumes deciding greedy-learning seeding once at startup. Orders and profile records written by v0.0.24 remain readable.

## Known limitations

- Indexed totals recorded before this release still include pages the quality gate refused. Only work absorbed afterwards is counted honestly, and no historical tally is rewritten.
- A run's page budget is fixed when the run starts, so narrowing a seed bound, or this release's priority correction, applies only to orders dispatched afterwards.
- Canonicalization and the recrawl priority repair future dispatches. Pages already stored under a non-canonical spelling remain under it until they are recrawled.
- Web-discovery seeding remains off by default. Once enabled, the queued pages per query remain the page cap times `YAGO_WEB_FALLBACK_MAX_RESULTS`; an operator raising either bound should size it against the fleet page rate governed by `crawler.max_pages_per_second`, `crawler.fetch_workers`, and `crawler.run_pages_per_minute`.
- The lease abandonment deadline reclaims work; it does not recover the frontier checkpoint the absent worker held, so a reclaimed run restarts from its durable queue state rather than that worker's in-memory progress.
- `MaximumHeartbeatActiveLeases` and the 500-row public result horizon remain fixed. The first is a bound both the node and the crawler validate against, so an operator-tunable value would let two independently configured processes reject each other's heartbeats; the second feeds reciprocal-rank fusion and the visible-evidence candidate bound, making it a retrieval invariant rather than retention policy.
- The crawl-order receiver still exposes no way to await its goroutines. This release removes the mutable package read that raced with test cleanup, but shutdown remains asynchronous.
- Profile and recrawl-schedule writes after successful ingest remain best-effort so they cannot roll back an indexed document. A failure is now counted and logged, but the page stays unscheduled for refresh until a later dispatch supplies its schedule.
