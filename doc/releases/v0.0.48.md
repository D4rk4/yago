## Abstract

YaGo v0.0.48 completes cold-read preparation for the live Bleve mappings opened by Scorch. Release v0.0.47 loaded every active segment through separate file descriptors, but production first-use queries still paid minor-fault and page-table work through the already-open mappings and exceeded the local deadline. The node now accesses each operating-system page through its live snapshot-owned mapping before readiness and refuses inconsistent or unavailable mappings. Stored data, APIs, settings, and deployment topology are unchanged. The correction removes this measured cold-read mechanism; it does not make one four-CPU process a hundreds-request architecture. That requirement remains an independently measured horizontal read-replica capacity problem.

## Changes

### Populate live search mappings before serving

Release v0.0.47 sequentially read about 2.30 GB of active persisted Scorch roots before production readiness. That eliminated physical input for a new `economics` query, but the first request still incurred 16,263 minor faults, used about 3.32 CPU-seconds, and exceeded the 1.8-second local-search deadline. Its unchanged repeat incurred 490 minor faults, used about 0.12 CPU-seconds, and returned ten rows in 58.9 milliseconds. Five other first-use common queries had the same incomplete result shape before completing in 51 to 102 milliseconds on repetition.

The root bytes were resident in the operating-system page cache, but the page tables of Scorch's already-open zapx mappings were not populated. Reading the same file through another descriptor does not populate those mapping entries. The node therefore keeps the v0.0.47 sequential file read and, while the referenced Scorch snapshot still owns segment lifetime, selects each persisted segment's live mapping.

After an active file reaches end of input, the node requires its byte total to equal the mapping length and accesses one byte at every operating-system page boundary. It checks startup cancellation before population and at every boundary. Persisted segments with an unavailable or nil mapping, invalid page size, file-to-mapping size disagreement, enumeration failure, or cancellation refuse index construction and readiness. In-memory and path-empty segments remain skipped; an explicitly non-nil empty mapping and empty file remain valid unchanged input.

The loader aggregates the page total and bounded access evidence across shards in its existing debug completion record. It does not copy the complete mapping, write segment bytes, lock pages, alter file metadata, change the writer generation, or change search results. The lexical warm-up still begins only after every active mapping has been populated.

### Keep concurrency capacity outside the request queue

Mapping population removes the measured arbitrary first-reader page-table charge. It does not remove query analysis, scoring, top-k selection, snippet work, or CPU contention. Existing production-sized synchronized-load evidence showed that corpus shape and CPU allocation determine how many broad queries a replica can finish within the fixed budget; one four-CPU process cannot honestly guarantee hundreds of simultaneous searches.

Per-process admission remains overload protection rather than a capacity promise. A deployment requiring hundreds of simultaneous bounded-latency reads must provision enough independently measured read replicas, or introduce a separately accepted bounded-retrieval backend. Any new runtime boundary still requires its own ADR and synchronized Docker, systemd, and package topology.

ADR-0069 records live-mapping population and amends ADR-0068's page-residency procedure. The release audit matched all 70 numbered ADR files to 70 unique index entries: 64 records are directly Accepted, ADR-0014 and ADR-0068 are Accepted with explicit amendments, ADR-0007, ADR-0030, and ADR-0035 are Superseded, and ADR-0000 is the non-decision proposal template. The previously delayed ADR-0063 remains implemented by conservative pre-serving filters and bounded post-open maintenance. No accepted or queued ADR implementation remains knowingly outstanding.

## Compatibility

- YaCy wire endpoints, Tavily-compatible endpoints, public response shapes, crawler contracts, stored documents, vault routing and shard formats, Bleve mappings and generation markers, package paths, image names, ports, listeners, services, and deployment topology are unchanged.
- No environment variable, Admin setting, default, navigation item, shelf row, Prometheus series, dependency, systemd unit, Compose control, or runtime service boundary changes.
- Bleve remains pinned to v2.6.1 with zapx v17.2.3 and writer generation v2. Mapping population is read-only and accepts already warm, empty, and in-memory indexes without a format transition.
- Upgrade from and rollback to v0.0.47 are format-compatible. Rollback removes live-mapping population and can restore the measured cold minor-fault deadline failure; it does not require a document rebuild.
- DDGS provider policy remains admin-opt-in. This release does not enable fallback by default or change provider engines, request syntax, result admission, crawl seeding, or human-facing provenance.

## Upgrade and rollback

1. After the immutable tag workflow succeeds, download the architecture-matching v0.0.48 Debian package. Verify its GitHub artifact attestation against repository `D4rk4/yago`, workflow `.github/workflows/release.yml`, tag ref `refs/tags/v0.0.48`, and the tagged source commit before stopping either service.
2. Follow the target's data-protection policy. Generic bare-metal nodes take one coordinated stopped backup. The documented `root@yagoseek.dev` exception preserves every existing archive under `/opt/yago/backups` and creates no new pre-upgrade backup; stage the verified package under `/opt/yago/releases`.
3. Stop `yago-crawler` and `yago-node`. Install the package with `dpkg -i` and confirm that package installation did not start either service automatically.
4. Start `yago-node` first. Allow the complete active-root read, live-mapping population, and lexical warm-up to finish before listeners and readiness appear. Verify exact v0.0.48 identity, health, readiness, indexed document total, stable restart count, nonzero mapping-page completion evidence, and bounded logs. Exercise several never-before-used common local queries before repeating them so acceptance covers both first-use and warm paths.
5. Start `yago-crawler` only after node search acceptance passes. Confirm a new logical session, continued crawl and index progress, DDGS materialization under the stored operator policy, and absence of a repeating lease-loss or reconnect loop.

For rollback to v0.0.47, stop both services, install the exact published v0.0.47 package, and start the node before the crawler. The index remains in the same writer generation and segment format, so no rebuild is expected. Rollback restores readiness without live-mapping population and can expose the same first-use minor-fault failure. Rollback to v0.0.38 retains the generation-v2 boundary and follows the complete derived-index rebuild procedure documented by v0.0.41.

## Known limitations

- Production success remains unconfirmed until the published v0.0.48 Debian package is deployed, mapping population reports nonzero work, and multiple genuinely new common local queries complete with results inside the fixed interactive budget before the crawler is started.
- File-backed pages and page-table entries remain reclaimable. A target whose active roots plus required heap, vault working set, page tables, and operating-system headroom do not fit available memory cannot claim the same first-use latency after reclaim.
- First readiness is delayed by both active persisted bytes and active mapping pages on every start. The loader intentionally fails closed; it has no skip setting because exposing a predictably cold mapping would recreate the incident.
- Synthetic mapping evidence does not establish a universal hundreds-request guarantee. Horizontal read capacity or a separately accepted bounded-retrieval service remains a future topology change with its own ADR and synchronized Docker, systemd, and package work.
- Bleve v2.6.1 and zapx v17.2.3 correct the known empty-middle-chunk writer class. They do not add an independent decoder allocation bound for arbitrary corrupt frequency data; that remains upstream work in `blevesearch/bleve#2393`.
- DDGS engines are external and can throttle, change markup, or return an honest empty result. Fallback remains disabled unless an administrator explicitly enables the applicable mode.
- Issue #3 remains open because a point-in-time resident-memory value does not establish growth or pressure. Use the existing Admin memory split together with cgroup events and repeated observations before attributing file-backed residency or anonymous memory.
