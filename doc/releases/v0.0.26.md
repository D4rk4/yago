## Abstract

YaGo v0.0.26 stops a failed search from looking like an empty index. The HTTP gate admitted four times the callers the search pipeline served, and the surplus waited on a blocking gate for the entire work budget; a caller admitted with no time left cannot search, so it received zero results and HTTP 200. Measured on the production constants, 12 of 16 concurrent callers were answered empty after 1.759 seconds. The wait is now bounded, and an empty answer the node cannot vouch for is labelled on every public surface. The YaCy wire shape, status codes, and response fields are unchanged; a legitimately empty search answers exactly as before.

## Changes

### The search pipeline no longer queues a caller past its own deadline

- The public HTTP gate admits `maximumConcurrentPublicSearches` concurrent searches. The pipeline gate behind it served `interactiveSearchConcurrentWork`, and the surplus waited on a blocking acquire inside a work context of the full interactive budget less its cancellation grace. A caller that won a slot late had no budget left to search with, and the pipeline answered it with zero results, one partial failure, and a nil error, which the surface wrote as HTTP 200. Driving the production searcher with its real budget, grace, and capacity, 12 of 16 concurrent callers received an empty answer after 1.759 seconds.
- The wait for a slot is now bounded, leaving the widest primary stage its complete budget. A caller that still cannot get a slot is told the node is at capacity, which is what happened, rather than being handed a zero it cannot distinguish from an empty index.
- The gate is sized from the processor count with a floor at the previous constant, so a larger machine serves what its front door admits. The same constant sizes four other pools, which is why it is derived rather than raised outright. On a four-core node the gate stays at its floor; there the bounded wait, not the sizing, is what changes the outcome.

### An empty answer says whether the node can vouch for it

- `Response.UnprovenZero` names the condition every surface needed and none had: no results, and either a lost source or an availability the session layer never settled. An answer that lost a source is discarded before the session layer can settle availability, so the two conditions are both necessary.
- `/yacysearch.json`, `/yacysearch.rss`, and `/yacysearch.html` set `X-Yago-Search-Availability: incomplete` and `Retry-After` on such an answer. The status stays 200 and the body is untouched: the wire shape is YaCy parity, third-party OpenSearch clients depend on it, and this project's own end-to-end poller reads any other status as "keep polling".
- RSS was the only surface that reported a lost source and an empty index with identical bytes. It now carries `yacy:partialFailure` in the already-declared `yacy` namespace, as the last channel element, omitted entirely when nothing failed.

### Diagnosis survives the failure that needs it

- `safeSearchSearcher` returned a zero `Response` alongside its error, discarding the partial failures the federation deliberately returns with it. Four named peer failures became one opaque stage timeout exactly when the answer went empty. It now keeps them; results are still discarded, because they were never filtered.
- `local-evidence` is a declared partial-failure source. As a bare literal no consumer recognised it: the peer-failure reporter fed it to the peer-hash parser and swallowed the error.

### A corrupted admin credential is refused instead of crashing the node

- `decodeArgon2id` validated the segment count, algorithm tag, version, parameter syntax, and base64 well-formedness of a stored password hash, but never the decoded salt and key lengths. A truncated record such as `$argon2id$v=19$m=65536,t=3,p=2$c2FsdA$` therefore decoded cleanly with a zero-length key, and `verifyPassword` asked the key derivation for a zero-length result. `x/crypto` builds that digest with `blake2b.New(0, nil)` and discards the error, leaving a nil digest inside a non-nil interface, so the write through it faulted: any login attempt against a damaged credential terminated the process instead of being refused. The decoder now enforces the salt and key lengths this package writes and rejects zero cost parameters, which is what the sibling API-key decoder already did for its own stored secret.

### The public portal stops contradicting itself

- The portal printed `Nothing found.` underneath its own banner saying no source answered. One page cannot both report that nothing answered and assert the index holds nothing. The line is suppressed when the result set is incomplete, and saved operator themes carrying the contradiction are repaired on load.

## Compatibility

- No environment variable, Admin setting, route, request field, response field, status code, public schema, listener, port, service, image name, package path, Bleve mapping, document encoding, or deployment topology changes. No dependency changes. No contract or wire-format change.
- Two additive surface signals: an advisory `X-Yago-Search-Availability` response header with `Retry-After`, and a `yacy:partialFailure` element in the existing `yacy` RSS namespace. Both appear only on an answer the node cannot vouch for; a compatible reader that ignores unknown headers and foreign-namespace elements sees exactly what it saw before.
- A legitimately empty search is unchanged: every source answered, nothing failed, availability settled, so HTTP 200 with zero results, no availability header, and no `yacy:partialFailure` element.
- An overloaded node now refuses a search in bounded time instead of holding the caller for the whole budget. Callers see the same HTTP 200 shape; the reason on the partial failure names capacity rather than a deadline.

## Upgrade and rollback

1. After the immutable tag workflow succeeds, download the architecture-matching v0.0.26 Debian package. Verify its GitHub artifact attestation against repository `D4rk4/yago`, workflow `.github/workflows/release.yml`, tag ref `refs/tags/v0.0.26`, and the tagged source commit before stopping either service.
2. Follow the target's data-protection policy. Generic bare-metal nodes take one coordinated stopped backup. The documented `root@yagoseek.dev` exception preserves every existing archive under `/opt/yago/backups` and creates no new pre-upgrade backup; stage the verified package under `/opt/yago/releases`.
3. Stop `yago-crawler` and then `yago-node`. Install the package with `dpkg -i` and confirm that package installation did not start either service automatically.
4. Start `yago-node` first, then `yago-crawler` after node readiness. Verify both versions, `/health`, `/ready`, and the configured listeners.
5. Watch for `local search capacity exhausted` on the interactive partial failure and for the availability header on empty answers. An empty answer that carries neither is a genuine miss.
6. Keep production verification observation-only.

For rollback, stop crawler and node, reinstall the v0.0.25 package, start and verify the node, and then start the crawler. No index rebuild or data restore is required. The older node resumes queueing surplus callers for the whole budget and resumes answering an unproven zero indistinguishably from an empty index. Stored documents and saved themes remain valid; a theme repaired by this release stays repaired and renders correctly on the older node.

## Known limitations

- The availability signal is advisory. `/yacysearch.*` keeps HTTP 200 for YaCy parity, so a client that reads neither the header nor the RSS element still cannot tell an unproven zero from an empty index. A strict opt-in that upgrades the status was designed and not shipped.
- Sizing the pipeline gate from the processor count adds no capacity to a small node. On a four-core deployment the gate stays at its floor, and a node whose processors are already consumed by crawling still sheds interactive searches; the release makes that visible and bounded rather than slow and silent.
- The recovery stages remain bounded by wall clock rather than by work, so a large index can exhaust the fuzzy budget before the automaton finishes. Bounding the automaton expansion instead was identified and left for a release that can measure it.
- Peers cut by the outbound call budget and query variants skipped on the swarm deadline still produce neither a result nor a partial failure, so a truncated fusion can still be cached as complete.
- Unverified remote snippet rows are dropped silently and the total is decremented without a recorded reason. The drop is deliberate anti-spam policy; only its observability is missing.
- A local admission starvation is still attributed to the peer whose fetch it blocked rather than to the local stage.
