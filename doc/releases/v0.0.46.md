## Abstract

YaGo v0.0.46 corrects the physical-I/O cold-search failure that remained after v0.0.45. Before readiness, the node now holds one Scorch snapshot and one file at a time while sequentially loading every active persisted search root into reclaimable operating-system cache, then runs the existing lexical warm-up. Missing files, cancellation, invalid reads, and close failures refuse startup without changing index bytes. APIs, stored formats, settings, and deployment topology are unchanged. First readiness is delayed by the active-root size and storage throughput. Synthetic load also confirms that hundreds of broad simultaneous searches require independently measured horizontal read capacity rather than a wider single-process queue.

## Changes

### Load active persisted search roots before serving

Release v0.0.45 reduced the production index to one active root per Scorch shard, but consolidation did not populate arbitrary postings and stored-data pages. Five first-use queries still failed at the fixed local-search deadline. The initial burst incurred 387 major faults and about 42 MiB of physical reads; the four admitted Bleve searches continued waiting on storage after their HTTP callers returned, so later requests were refused for exhausted capacity.

After any rebuild and bounded segment consolidation, the disk index now obtains one referenced Scorch snapshot at a time and enumerates only that snapshot's nonempty persisted segment paths. It reads each active file sequentially to end through one reusable 4 MiB window, with one snapshot and one file open at a time. Holding the snapshot prevents the Scorch purger from retiring an active file during the read. Retained inactive snapshots and in-memory segments are not read.

The loader checks cancellation before every shard and file and between windows. Snapshot acquisition, path opening, read, file close, snapshot close, invalid negative reader output, or a no-progress reader refuses index construction. Joined cleanup failures remain visible. Files are opened by basename inside their exact index directories. The operation does not write segment bytes, change their size, mode, or modification time, advance the writer generation, or alter mappings.

The existing lexical warm-up runs only after every active root has been read. The node does not open listeners or report readiness until both stages complete, moving predictable sequential storage work ahead of interactive admission instead of assigning scattered first-use faults to unrelated users.

### Preserve an honest read-capacity model

The loaded pages are operating-system file cache, not pinned application memory. A latency-sensitive deployment must budget residency for the complete active roots together with the node heap, document-vault working set, and operating-system headroom. Startup duration is proportional to active-root bytes and available storage throughput. Later memory pressure may reclaim pages, so cold synchronized validation on the actual corpus remains part of capacity planning.

The production-sized synthetic gate deliberately exercised 100 and 200 simultaneous distinct queries at four and eight CPUs. Active-root loading substantially reduced first-round page faults, but the remaining CPU and scoring work still exceeded the response budget for many requests. The result rejects a wider queue or higher in-process concurrency as a general solution. A deployment requiring hundreds of broad simultaneous searches must use enough independently measured read replicas, or a separately accepted bounded-retrieval backend, so every replica remains below its measured cold CPU and cache limit. This release preserves the narrow search and document-store interfaces needed for that topology but does not introduce a new runtime service boundary.

ADR-0068 records the cache-loading decision and its capacity boundary. The release audit matched all 69 numbered ADR files to 69 index entries: 65 live decisions are Accepted, ADR-0007, ADR-0030, and ADR-0035 are explicitly Superseded, and ADR-0000 is the non-decision proposal template. The previously delayed ADR-0063 remains implemented by conservative pre-serving filters and bounded post-open maintenance. No accepted or queued ADR implementation remains knowingly outstanding.

## Compatibility

- YaCy wire endpoints, Tavily-compatible endpoints, public response shapes, crawler contracts, stored documents, vault routing and shard formats, Bleve mappings and generation markers, package paths, image names, ports, listeners, services, and deployment topology are unchanged.
- No environment variable, Admin setting, default, navigation item, shelf row, Prometheus series, dependency, systemd unit, Compose control, or runtime service boundary changes.
- Bleve remains pinned to v2.6.1 with zapx v17.2.3 and writer generation v2. The loader is read-only and accepts already bounded, already warm, empty, and in-memory indexes without a format transition.
- Upgrade from and rollback to v0.0.45 are format-compatible. Rollback removes the explicit active-root loading stage and can restore the cold physical-I/O failure; it does not require a document rebuild.
- DDGS provider policy remains admin-opt-in. This release does not enable fallback by default or change provider engines, request syntax, result admission, crawl seeding, or human-facing provenance.

Verify its GitHub artifact attestation against repository `D4rk4/yago`, workflow `.github/workflows/release.yml`, tag ref `refs/tags/v0.0.46`, and the tagged source commit before stopping either service.
2. Follow the target's data-protection policy. Generic bare-metal nodes take one coordinated stopped backup. The documented `root@yagoseek.dev` exception preserves every existing archive under `/opt/yago/backups` and creates no new pre-upgrade backup; stage the verified package under `/opt/yago/releases`.
3. Stop `yago-crawler` and `yago-node`. Install the package with `dpkg -i` and confirm that package installation did not start either service automatically.
4. Start `yago-node` first. Allow the complete active-root read to finish before listeners and readiness appear. Verify exact v0.0.46 identity, health, readiness, indexed document total, stable restart count, cache-loader byte and segment totals, and bounded logs. Exercise several never-before-used common local queries before repeating them so acceptance covers both first-use and warm paths.
5. Start `yago-crawler` only after node search acceptance passes. Confirm a new logical session, continued crawl and index progress, DDGS materialization under the stored operator policy, and absence of a repeating lease-loss or reconnect loop.

For rollback to v0.0.45, stop both services, install the exact published v0.0.45 package, and start the node before the crawler. The index remains in the same writer generation and segment format, so no rebuild is expected. Rollback restores readiness without the complete active-root read and can expose the same first-use physical faults. Rollback to v0.0.38 retains the generation-v2 boundary and follows the complete derived-index rebuild procedure documented by v0.0.41.

## Known limitations

- Production success remains unconfirmed until the published v0.0.46 Debian package is deployed, active-root loading completes, and multiple genuinely new common local queries complete within the fixed interactive budget before the crawler is started.
- Cache residency is reclaimable. A target whose active roots plus required heap, vault working set, and operating-system headroom do not fit available memory cannot claim the same first-use latency after reclaim.
- The first readiness delay is proportional to active persisted bytes and storage throughput on every start. The loader intentionally fails closed; it has no skip setting because exposing a predictably cold index would recreate the incident.
- Synthetic burst results describe the exact corpus and CPU allocations exercised. They explicitly disprove a universal single-replica hundreds-request guarantee. Horizontal read capacity or a separately accepted bounded-retrieval service remains a future topology change with its own ADR and synchronized Docker, systemd, and package work.
- Bleve v2.6.1 and zapx v17.2.3 correct the known empty-middle-chunk writer class. They do not add an independent decoder allocation bound for arbitrary corrupt frequency data; that remains upstream work in `blevesearch/bleve#2393`.
- DDGS engines are external and can throttle, change markup, or return an honest empty result. Fallback remains disabled unless an administrator explicitly enables the applicable mode.
- Issue #3 remains open because a point-in-time resident-memory value does not establish growth or pressure. Use the existing Admin memory split together with cgroup events and repeated observations before attributing file-backed residency or anonymous memory.
