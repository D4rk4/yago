## Abstract

Yago v0.0.82 reduces HTTP 409 responses for long Tavily-compatible searches. A long relaxed query can now return passages that hold three of its terms. The relaxed minimum match no longer repeats its document walk during scoring. The total interactive search deadline increases from 1.8 seconds to 3.6 seconds, so a slow search can take longer before it answers. The crawler image updates the libxml2, OpenSSL, and Firefox ESR package revisions. No setting, storage, or wire-format migration is necessary. Rollback restores the 1.8-second deadline, the previous long-query passage rule, and the vulnerable libxml2 revision.

## Changes

### Long-query passage rule

- A relaxed-only local match still needs one bounded passage of a single field. That passage must show the relaxed coverage, capped at three query terms.
- When the query has more than three mixed alphanumeric identifiers, the passage must show every identifier.
- Queries with five or fewer requirements are unchanged. Retrieval coverage, cross-field refusal, and the refusal of uninspected candidates are unchanged.
- ADR-0047 records the amended rule.

### Candidate-led minimum match

- When the lexical candidate snapshot is complete, the ranked scoring pass evaluates the relaxed minimum match only at the snapshot documents.
- An incomplete snapshot, or a search without a snapshot, keeps the previous walk over the rarest-term drivers.
- Hits, scores, and term locations do not change. ADR-0090 records the decision.

### Search deadline

- Public interactive search, including the Tavily-compatible `POST /search`, uses a total deadline of 3.6 seconds instead of 1.8 seconds.
- In `Always` web mode, the exact primary stage stops at 3.2 seconds instead of 1.4 seconds. The web provider stops 50 milliseconds before the request deadline.
- The supplement decision point (600 milliseconds), the assembly reserve (100 milliseconds), and the minimum web window (1 second) do not change. A shorter caller deadline still applies.
- ADR-0091 records the decision.

### Crawler image package baseline

- The crawler image pins `libxml2=2.13.9-r3`. This corrects CVE-2026-86144 (HIGH) in `2.13.9-r2`.
- The image also pins `firefox-esr=153.7.0-r0`, `libcrypto3=3.5.9-r1`, and `libssl3=3.5.9-r1`. The Alpine 3.24 index no longer published the earlier pinned revisions.
- The tag-gated Firefox integration test compiles again against the current fetch request signature.

### Project instructions

- `AGENTS.md` requires ASD-STE100 Simplified Technical English, Issue 9, for new and changed English prose.

## Compatibility

Tavily request fields, success fields, detail-only error envelopes, and retry headers are unchanged. YaCy wire endpoints, the RWI format, the crawler contract, and the document format are unchanged.

A slow search can now take up to 3.6 seconds before it answers. Callers with a client timeout below 3.6 seconds can see more client timeouts. A fast search still returns as soon as its work is complete.

The crawler image now ships Firefox ESR 153 instead of Firefox ESR 140. Browser settings, the Marionette fetch path, the non-root identity, and the entrypoint are unchanged. Bare-metal and package installations use the Firefox ESR that the host operating system supplies.

No environment variable, listener, service topology, or operator setting changes.

## Upgrade and rollback

1. Download the published package for the host architecture. Verify its GitHub artifact attestation against repository `D4rk4/yago`, workflow `.github/workflows/release.yml`, source ref `refs/tags/v0.0.82`, and the commit that the tag identifies.
2. Back up the configured data directory under the backup policy of the deployment. Stop `yago-crawler` and `yago-node`. Install the package with `dpkg -i`. Package installation enables the services but does not start them.
3. Start `yago-node`. Verify health and readiness. Start `yago-crawler`. Verify its connection and its work progress. No reindexing or data conversion is necessary.
4. For rollback, stop both services, install the attested v0.0.81 package, and start and verify the node before the crawler. Rollback restores the 1.8-second deadline and the previous long-query passage rule. A rollback of the crawler image restores the vulnerable libxml2 revision.

Container operators use the exact immutable `v0.0.82` image tags. Systemd and package deployments use the same binaries and runtime configuration.

## Known limitations

- This release does not remove every HTTP 409. A search that loses a required source still asks for a retry.
- On a synthetic 105,000-document corpus, the candidate-led minimum match examined 170,353 documents instead of 293,918 for twelve synthetic long queries. The local wall time did not show a clear change. No measured production reduction is claimed.
- After the long-query passage rule, two of twelve synthetic long queries still returned no rows. Each had at most three relaxed candidates.
- The mandatory release-scope review found one open issue with the exact `bug` label and none with the exact `enhancement` label. [D4rk4/yago#3](https://github.com/D4rk4/yago/issues/3) was reviewed and left open. The available evidence does not confirm a memory leak or a memory pressure defect, and no safe issue-specific correction was identified within this candidate. No memory-use improvement is claimed.
