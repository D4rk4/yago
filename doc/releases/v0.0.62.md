## Abstract

Yago v0.0.62 applies the same web-result relevance check at every Tavily search depth and keeps XML sitemaps out of future document ingestion. Non-advanced API searches can return fewer results when provider rows lack query evidence; rejected rows are not seeded for crawling. Sitemap URLs discovered during ordinary crawling remain subject to existing crawl limits. Existing sitemap documents are not removed automatically. The release also includes transport and container-library security updates. YaCy and Tavily wire shapes, stored formats, runtime settings, and deployment topology remain compatible with v0.0.61. Upgrade the node and crawler together; no migration or index rebuild is required.

## Changes

### Apply web relevance checks at every API depth

Non-advanced Tavily requests previously bypassed the web provider's bounded query-evidence check. An unrelated engine answer could therefore end the engine search, appear in the API response, and enter crawl discovery. All depths now use the shared relevance check before accepting provider rows. A rejected engine answer allows the existing bounded engine search to continue. Both conditional supplementation and parallel web search reject irrelevant rows before serving or seeding them. An answer containing only rejected rows remains an honest empty answer when retrieval itself succeeded.

Search-depth and source selection, provider consent, domain constraints, safe-search evidence, caching boundaries, and the 1.8-second search deadline are preserved. The API gains no fields or provider marker.

### Treat sitemap XML as crawl discovery

An XML sitemap fetched through an ordinary URL crawl previously fell through to generic XML text extraction. Its locations and scheduling metadata could become a searchable document while its URLs were not discovered.

The crawler now recognizes the Sitemaps XML namespace and its URL-set and sitemap-index roots, including a legal UTF-8 byte-order mark and XML prologue. It submits extracted locations through the normal frontier under the existing sitemap URL limit, crawl scope, depth, page budgets, and security policy. A valid sitemap counts as fetched, without document ingestion or a parse-failure increment. Ignoring robots directives does not enable sitemap indexing. Malformed recognized sitemaps cannot fall back to generic text extraction; an extra root or invalid trailer is refused. Ordinary XML, RSS, and Atom retain their existing behavior.

### Update the dependency security baseline

The node, crawler, shared crawl contract, and isolated end-to-end graphs pin gRPC
v1.83.2 instead of v1.83.1. This includes the missing-authority-header correction
in [GO-2026-6443](https://pkg.go.dev/vuln/GO-2026-6443). The release gate reported an
affected transport call path. The upstream advisory describes an xDS routing
panic; no exploitation or deployment-specific panic was established here. The
patch is applied without suppressing the scanner finding or adding a dependency.
Associated existing Go modules follow the dependency versions required by gRPC.

The crawler container pins its existing libexpat library to Alpine `2.8.5-r0`
instead of retaining `2.8.4-r0` from the base image. This includes the malformed
UTF-16 correction in
[CVE-2026-93990](https://github.com/libexpat/libexpat/releases/tag/R_2_8_5).
Its existing CA certificates pin also advances to `20260909-r0`; the previous
exact package is no longer in the configured Alpine v3.24 package indexes. The base image
digest and remaining package pins are unchanged. Bare-metal library and browser
security updates continue to come from the host operating system.

### Advance the compatibility baseline

The reusable-module API gate now compares against the exact published v0.0.61 tag and source commit. No reusable-module API change is introduced.

## Compatibility

- YaCy peer exchange and search endpoints, Tavily request and response shapes, node-crawler messages, and stored document, vault, frontier, and index formats remain compatible with v0.0.61.
- No dependency, runtime setting, environment variable, listener, service, image repository, or deployment topology is added.
- External web search and crawl seeding retain their existing operator controls and defaults. Existing effective operator values remain in force.
- The relevance change intentionally removes provider rows that fail the existing visible-evidence threshold, including at basic, fast, and ultra-fast depths.

## Upgrade and rollback

1. Wait for the tag workflow to finish verification, native container checks, package builds, attestations, and anonymous registry verification.
2. Download the published Debian package matching the host architecture. Verify its attestation against repository `D4rk4/yago`, workflow `D4rk4/yago/.github/workflows/release.yml`, source ref `refs/tags/v0.0.62`, and the exact tagged source commit. Verify the staged bytes and package name, version, and architecture before installation.
3. Back up the data on a generic bare-metal deployment. An explicitly designated no-new-backup target preserves every existing archive unchanged and stages the package under `/opt/yago/releases`.
4. Stop `yago-crawler` and `yago-node`, then install with `dpkg -i`. The package enables the services but does not start them.
5. Start `yago-node` and verify its exact version, health, readiness, and nonempty index before starting `yago-crawler`. Confirm a current crawler session, continuing work, and stable restart counters.

Rollback to the published v0.0.61 package is data-format compatible. Download and verify the architecture-matching package against its own tag, source commit, and release-workflow attestation, and apply the same target backup policy. Stop both services, install that verified package, then start and verify the node before the crawler. Rollback restores the former web-verification bypass, sitemap text-ingestion behavior, and older gRPC security baseline.

Container rollback uses the verified v0.0.61 image pair. Stop both containers,
select those exact-version images, and start and verify the node before the
crawler. The v0.0.61 crawler image also restores libexpat `2.8.4-r0` and the
CVE-2026-93990 exposure corrected in this release.

## Known limitations

- Previously stored sitemap documents remain in the index until an operator removes them through Admin → Index. The parser correction applies to future fetches.
- Web relevance uses bounded visible query evidence; it is not a guarantee of semantic relevance.
- Crawl discovery remains asynchronous and best effort. Read-only operational evidence showed seed-publication write deadlines; this release does not change the existing ten-second write budget or claim to resolve storage or lock latency. Queue publication does not guarantee successful fetching or admission by the document-quality gate.
- The mandatory review of open issues carrying the exact `bug` or `enhancement` label found only [issue #3](https://github.com/D4rk4/yago/issues/3). Its v0.0.32/v0.0.35 memory snapshots do not establish current growth, pressure, or an OOM condition. No safe reporter-specific correction was established within this candidate; the issue remains open pending current evidence.
