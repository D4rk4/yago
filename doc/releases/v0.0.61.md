## Abstract

Yago v0.0.61 preserves completed search results across partial failures and deadlines, and adds opt-in web supplementation when fewer than 100 verified primary candidates are available. Existing enabled installations now send sparse nonempty searches externally; web search remains disabled by default. Crawl queue notifications wake all waiting receivers, and persistent frontier recovery uses one bounded path. The release also removes unused internal implementations and updates transport and cryptography dependencies. YaCy and Tavily wire shapes, stored formats, listeners and service topology remain compatible with v0.0.59. Upgrade both binaries together; no migration or index rebuild is required for that upgrade.

## Changes

### Keep the API gate tied to its configured baseline

The v0.0.60 release preparation advanced the API baseline to the previous published v0.0.59 and passed the actual four-module API comparison. A separate test still compared that file with a hard-coded v0.0.56 identity, so CI stopped the release before building artifacts. The duplicate assertion is removed. The gate test reads the configured baseline, admits compatible output and still refuses an incompatible API or the correct tag paired with an incorrect source commit. The baseline file and the tag-identity checks remain authoritative. This correction changes test policy only; it does not change either runtime binary.

### Preserve useful index answers within the deadline

A strict local answer could be discarded when a later relaxed search failed. Completed pages could also be lost at the deadline or wait behind unnecessary session-extension work. These paths now preserve the completed rows and their incomplete-source evidence. A page completed at cancellation is returned without being cached as a complete session. Already available pages bypass extension waiting, and a cancelled extension waiter releases its admission.

A complete empty lexical candidate set now avoids scored analyzer reads that cannot add a result. Primary-stage budgeting also accounts for time already spent waiting for an execution slot. First-seen-bounded requests do not reserve an external-provider interval because they cannot use that provider. Honest empty results remain distinguishable from failed or unfinished retrieval.

### Supplement a sparse primary result window

ADR-0084 changes the optional provider trigger from an empty answer to a verified candidate-breadth decision. The node counts distinct admissible local and federated candidates after request filters, safety checks, canonical URL deduplication and content-cluster consolidation, before pagination. An estimated index total or the number of rows requested by a client does not determine this decision.

| Operator mode | Behavior |
| --- | --- |
| `disabled` | No web retrieval. This remains the default. |
| `explicit` | Request consent is required; supplement when the primary window has fewer than 100 candidates. |
| `enabled` | Supplement when the primary window has fewer than 100 candidates, including nonempty answers. |
| `always` | Start web retrieval alongside local and federated retrieval. |

The Admin label for enabled mode is `Supplement below 100 results`. Mode changes apply to new requests without a node restart. The current provider and session pipeline is rebuilt when the mode changes; in-flight requests retain their existing bounded work.

Conditional search reserves one second for web retrieval and 100 milliseconds for final assembly inside the existing 1.8-second total, including execution-slot waiting. A shorter caller deadline takes precedence. Web retrieval starts as soon as the sparse-window decision is available. Applicable bounded local recovery overlaps it and can be cancelled when a useful web addition completes the answer.

Empty, rejected and duplicate-only engine or cached batches do not end supplementation while another eligible engine and time remain. The first validated batch adding a distinct admissible URL can complete the web branch. Completed primary rows survive provider failure. Existing reciprocal-rank fusion combines the sources before final ordering and pagination.

The threshold does not promise 100 returned URLs. Public result limits, the 500-result paging horizon and the at-most-20 normalized provider rows remain in force. Local-only requests, unsupported content domains and first-seen-bounded searches remain ineligible. Internal provenance stays `ddgs`; source labels remain `web`, and Tavily payloads gain no provider field. Optional crawl seeding remains asynchronous and independently bounded.

### Wake waiting crawlers and retain one recovery path

Several queue publications could collapse into one notification, leaving an idle receiver asleep while work remained queued. Queue changes now broadcast a generation change to all current waiters. A receiver captures that generation before checking eligibility, so publication between the check and the wait cannot be lost. Cancellation and per-session lease capacity still apply.

Persistent crawler checkpoints now require bounded recovery at the internal interface. Host progress is committed through page completion. Identical host-generation updates preserve the stored state; conflicting updates are refused. Session-aware leases keep checkpoint affinity, while deferred and legacy sessionless leases retain their expiry-and-requeue behavior.

Progress and settlement retries share the existing bounded jitter calculation. The terminal outbox, explicit lease ownership, session fences, host politeness, origin admission and restart recovery remain in use.

### Remove unused internal paths

The maintenance pass removes predecessor calibration and host-ranking implementations, an unused ingest-side cluster-deletion chain, sessionless transport adapters, parser convenience wrappers, old browser observation callbacks, admin listing and asset projections, and redundant startup wrappers. Useful tests now call the active bounded and session-aware paths. Scalar slice copies and first-nonempty selection use the standard library; duplicate integer validation uses one existing function.

Tavily error assembly no longer carries values that its detail-only envelope discarded. Direct cryptographic random generation no longer has artificial failure paths that Go's `crypto/rand.Read` cannot return. Token formats, entropy sizes, password hashing, credential admission and errors from arbitrary readers or persistent storage are retained. The reusable-module compatibility baseline advances to the exact published v0.0.59 commit for this release.

The in-memory Bleve backend now closes its workers through the existing index lifecycle, including an idempotent second close. This is a lifecycle correction, not a claim that the open reporter-host memory issue is resolved. Interim review documents are absent from the release source tree.

### Update the dependency security baseline

The node, crawler and shared crawl contract use gRPC v1.83.1 instead of v1.82.1, including the fragmented HTTP/2 receive-memory correction described in [the upstream advisory](https://github.com/grpc/grpc-go/security/advisories/GHSA-vp52-pcj8-j9qc). The node and isolated end-to-end graphs use x/crypto v0.55.0, including the authentication restriction correction in [GO-2026-6303](https://pkg.go.dev/vuln/GO-2026-6303). Associated x/net, x/sys, x/text and generated RPC dependency pins are synchronized with those updates.

The crawler container pins its existing libblkid and libmount packages to Alpine `2.42.3-r1`. Bare-metal library and browser security updates continue to come from the host operating system; the Debian package does not bundle those host libraries.

## Compatibility

- YaCy endpoints and peer exchange, Tavily request and response shapes, node-crawler messages, document and vault formats, and the Bleve segment format remain compatible with v0.0.59.
- No environment variable, listener, service, image repository or deployment topology is added. Existing web mode bootstrap values and stored overrides are preserved.
- Enabled web mode has an intentional privacy and latency change: sparse nonempty requests can now leave the node. Operators requiring request-by-request consent should use `explicit`; operators requiring no external search should use `disabled`.
- Public search remains document-backed. RWI remains the YaCy compatibility and exchange format. No upstream Tavily provider or additional runtime service is introduced.
- Upgrade from v0.0.59 requires no data migration or index rebuild. Node and crawler must still be upgraded together.

## Upgrade and rollback

1. Wait for the immutable tag workflow to complete its verification, native container checks, package builds, attestations and anonymous registry gate.
2. Download the architecture-matching published Debian package. Verify its attestation against repository `D4rk4/yago`, signer workflow `D4rk4/yago/.github/workflows/release.yml`, source ref `refs/tags/v0.0.61` and the exact tagged source commit. Verify the staged package bytes and its version and architecture before installation.
3. Apply the target's data-protection policy. Generic bare-metal installations take a coordinated backup. An already authorized no-new-backup target preserves every existing archive unchanged and stages the verified package under `/opt/yago/releases`.
4. Stop `yago-crawler` and `yago-node`, then install the package with `dpkg -i`. Package installation enables the services but does not start them.
5. Start `yago-node`, verify the exact version, health, readiness, indexed-document availability, listeners and stable restart counters, then start `yago-crawler`.
6. Confirm a current crawler session, continuing crawl work and the absence of a repeating lease-loss or reconnect loop. Check the effective web mode and use bounded API probes for search acceptance.

Rollback to the published v0.0.59 package is data-format compatible. Stop both services and install the matched older package before starting the node and then the crawler. Rollback restores the old web trigger, reintroduces the search/queue failure paths and uses the older dependency baseline; it is not a security-equivalent steady state.

## Known limitations

- External engines can throttle requests, change their markup, return rejected or duplicate rows, or provide an honest empty answer. A time reserve cannot guarantee provider availability or a full result page.
- The 100-candidate threshold and one-second reserve are product choices. Sparse enabled-mode searches can use more outbound requests and take longer than their local-only answer.
- Bounded admission remains necessary under load. This release does not provide a horizontal read tier or guarantee hundreds of simultaneous successful full HTTP searches.
- Issue #3 remains open. Process RSS can include mapped index pages; the available reporter evidence does not establish the current memory behavior of that installation.
- Static analyzers, race tests, one deterministic shuffle and short fuzz smoke cover different failure classes. The unchanged NilAway baseline remains explicit debt, and no check proves every possible interleaving or input safe.
