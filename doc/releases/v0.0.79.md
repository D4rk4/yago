## Abstract

Yago v0.0.79 reworks the shared `yagopdf` reader that the crawler and node fetch-on-extract use. It unpacks object streams, opens standard-security documents whose user password is empty, resolves fonts per page, places spaces from glyph widths, and reads only pages in the current page tree. On 122 synthetic producer files, readable documents rise from 54 to 108. The extraction generation rises from 1 to 2, so each stored document is fetched in full and extracted again on its next recrawl. Upgrade node and crawler together. No storage conversion, listener, setting, or YaCy wire change is required. Rollback to v0.0.78 needs no conversion but refetches documents that v0.0.79 extracted.

## Changes

### Document structure

- Objects packed into object streams are now unpacked before reading, so page, font, resource and title objects stored that way are found. Unpacked object-stream data shares the 32 MiB per-document decoding budget and is capped at 8 MiB. Object streams nested inside other object streams are not unpacked.
- Text now comes only from the content streams of pages in the current page tree, reached from the catalog of the newest trailer, and from the form objects those pages use. A page removed by an incremental update is no longer read. A file without a usable page tree falls back to its other streams but skips streams named as scripts, attachments or form data.
- A stream whose direct numeric `/Length` ends at `endstream` now ends exactly there, so bytes inside stream data cannot add or replace objects. Object headers inside comments, strings and malformed objects are now ignored.

### Encrypted documents

- A document protected by the standard security handler, revisions 2 to 6 with RC4 or AES, is now read when it opens with an empty user password and its permissions allow text extraction.
- A document that needs a password, forbids extraction, or uses another security handler is still reported as unreadable. The reader does not guess passwords or bypass permissions.
- The MD5 and RC4 primitives required by revisions 2 to 4 are used only to decrypt such documents. Their gosec exceptions are exact file-and-rule pairs in two files, and five Semgrep suppressions name the exact rule on the exact line.

### Text

- Content streams are now split into tokens by PDF syntax. An operator name inside a string, a name or a longer token no longer opens or closes a text block.
- Each page and form now resolves font names through its own resources, so the same font name can map to different fonts on different pages.
- Spaces are now placed from font glyph widths, text position, size, spacing and scaling. A forward gap wider than 0.102 em separates words; a backward move of more than 0.2 em, or a vertical move of more than half the font size, starts a new line. This repairs words that per-glyph producers, such as Chromium, previously ran together.
- Latin ligatures U+FB00 to U+FB06 are written as their separate letters. Control characters, bidirectional formatting marks and Unicode noncharacters are dropped; tabs and line feeds are kept.
- PostScript text now comes only from strings consumed by a PostScript show operator. Other strings in a PostScript program are no longer written as text.

### Title

- The title now comes only from the `/Title` of the document information dictionary named by the newest trailer and is capped at 4 KiB. The v0.0.78 fallback to the first `/Title` string in files without an information dictionary is removed, because that string is often an outline label. The crawler still uses the first text line when the PDF title is empty.

### Bounds

- New fixed caps cover the title (4 KiB), glyph-width entries (65,536 per document), dictionary nesting (64 levels), security strings (256 bytes) and unpacked object streams (8 MiB). Existing stream, document, text, object-scan, indirect-object, font and graphics-state bounds are unchanged.

### Extraction generation

- `yagocrawlcontract.CurrentExtractionGeneration` changes from 1 to 2. A stored document with an older generation is not treated as current, so its next scheduled recrawl fetches the full response instead of a conditional one and extracts it again. The existing Admin → Index extraction-generation action can queue older documents sooner.

### Release engineering

- The reusable-module API gate now accepts a deliberate change only through `tools/api-compatibility-exceptions` (ADR-0089). Each entry names the baseline tag, the module and the exact change line. An entry for another baseline tag, or one that matches no reported change, fails the gate. The single entry accepts the generation change against `v0.0.78`.
- The NilAway ratchet now records 90 reviewed locations instead of 82. Each new location is guarded by a preceding length or prefix check or a fixed AES output size.

## Compatibility

- YaCy wire: unchanged.
- Tavily-compatible API: request and response shapes are unchanged. Fetch-on-extract may now return text for PDFs it previously refused, and its text and titles for other PDFs may differ.
- Node-crawler messages: the message format is unchanged; documents now carry extraction generation 2. A node and crawler on different releases treat documents from the other side as not current, so upgrade both together.
- Storage: no collection, record format, or index mapping changes. Existing data needs no conversion. Previously indexed PDFs keep their stored text and titles until their next recrawl.
- Recrawl load: because every stored document has generation 1 or none, the first recrawl of each document after the upgrade fetches the full response. Expect more fetch traffic and indexing work during one recrawl cycle.
- Reusable-module API: one deliberate change in `yagocrawlcontract`, the value of `CurrentExtractionGeneration`, recorded against `v0.0.78`. No other exported API changes.
- Settings: no environment variables or admin settings are added, removed or changed. No listener, port, or service changes.

## Upgrade and rollback

- Upgrade the node and crawler in the same maintenance window. On a generic bare-metal host:
  1. Fetch the release `.deb` and verify its artifact attestation against repository `D4rk4/yago`, the release workflow, tag `v0.0.79` and its source commit.
  2. Back up `/opt/yago/data`.
  3. Stop `yago-node` and `yago-crawler`.
  4. Install with `dpkg -i`.
  5. Start both services and confirm they report healthy.
- Rolling back to v0.0.78 needs no data conversion. Documents extracted by v0.0.79 carry generation 2, which v0.0.78 does not treat as current, so they are fetched in full again on their next recrawl and extracted with the v0.0.78 reader.

- Dockerized Semgrep 1.168.0 (`--config auto --error`) reported no findings. Dockerized Trivy 0.72.0 reported no HIGH or CRITICAL vulnerability, secret, or misconfiguration finding in the source tree or in the locally built node and crawler images.
- `make e2e` built current-source node and crawler images and passed both suites. The node suite passed all 20 tests, including the tests against a real Java YaCy peer. The crawler suite passed all 8 tests, including the live lifecycle test that restarts only the node while the crawler runs and then only the crawler while the node runs, with crawl work progressing after each restart. A first run failed one Java YaCy global-search test because the host load average exceeded the Java peer's remote-search threshold of 2.0 while an unrelated local file search ran; after that search stopped, the complete rerun passed.
- API gate tests: a recorded exception admits only its exact change; an entry for another module, another change, an unused entry, and an entry for another baseline tag are each refused.
- Hostile-input tests cover nested and oversized object streams, form and page-tree cycles, injected `endstream` and object headers, forged pages in malformed objects, removed pages, outline titles, operator names inside tokens, oversized font, width and CMap tables, deep `/Parent` chains, filter-chain bombs, documents that need a user password, and forbidden extraction.
- Fixtures: 11 producer files and 14 encrypted files were written by real PDF producers and qpdf from invented text; each directory's `generate.sh` reproduces them. Fixture metadata contains no personal names or local paths.
- Synthetic support audit: 122 generated files from 14 producer families, including 20 encrypted and 20 with object streams. Compared with v0.0.78, readable files rose from 54 to 108, mean text recall from 0.35 to 0.84, median recall from 0 to 0.97, and correct titles from 56 to 105. No file lost recall. Of the 114 files that `pdftotext` reads, this release reads 106.
- Anonymization audit: the memo, feature rows, documentation, commit text, and new fixtures contain no copied operational input.

## Known limitations

- Only an existing text layer is read; no OCR is performed.
- Type 3 fonts, and composite fonts without a `/ToUnicode` map that use a predefined CMap other than Identity, usually yield little or no text. In the synthetic audit these account for most of the 14 unreadable files, together with truncated files and files with bytes before the `%PDF` header.
- Reading order follows content-stream order. Multi-column layouts, tables, vertical writing and right-to-left text may come out in a different order than a reader would see.
- Form field values, annotations and attachments are not extracted.
- PDF parsing is bounded by size and count but is not yet cancelled when a fetch-on-extract request deadline expires.
- Open issue #3 (node memory use) is not addressed by this release.
