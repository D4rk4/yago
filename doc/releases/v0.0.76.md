## Abstract

Yago v0.0.76 reduces storage write traffic, adds conditional recrawl, and hardens peer protocol handling. Contended vault writes now commit in groups, repeated peer-caller observations skip redundant roster writes, and shards reopened after compaction or split keep deferred-fsync mode. The crawler revalidates unchanged pages with origin validators. Outbound peer POSTs use multipart form data, peer-protocol clients refuse redirects, and peer messages must name their sender. Search reuses term postings within one query and selects complete-query snippets. Dependency and crawler image security updates are included. No setting, listener, or storage conversion is required. Node and crawler may be upgraded in either order; rollback to v0.0.75 needs no conversion.

## Changes

### Storage write reduction

- Grouped commits for contended vault writes. When shard contention forces the sharded vault to serialize writers, the writer that enters the serialized path now applies up to 32 queued updates in one transaction and commits once, instead of one commit and one disk flush per update. If any update in a group fails, panics, or reaches an unreadable shard root, the group rolls back and every member runs again alone, so each caller observes only its own outcome. A failed group commit is reported to every member. A writer cancelled before its group forms writes nothing. Uncontended writes keep their per-shard path.
- Caller observations without repeated roster writes. A peer that calls the node again within five minutes refreshes its reachable membership in memory without a peer-roster write when its stored row has the same verification level, no retry cooldown, the same answered endpoint, and the same seed apart from its statistics. Any of those differences, an unreadable stored row, or five elapsed minutes still writes the row. An unverified (junior) caller observation no longer opens a write transaction for a peer that is already known.
- Deferred-fsync mode kept across shard reopen. A shard reopened after compaction or split previously returned to a flush on every commit until the mode was set again; it now keeps the vault's current mode. Nodes that never enable deferred fsync are unaffected.

### Conditional recrawl

- After a full fetch is stored, the node keeps the page's valid origin validators and the stored document's revision on its recrawl schedule. A due recrawl order carries them only while the stored document is present, current, and unchanged.
- The crawler sends those validators only to the exact target, strips them on every redirect hop, and reports a solicited `304 Not Modified` as one not-modified observation without reading a body. An unsolicited or malformed `304` is retried at most once inside the original deadline.
- The node records a matching observation in one transaction that advances the next due time without touching the stored document. When the node refuses the observation, the crawler fetches the page in full.
- New Prometheus counters: `crawl_recrawl_conditional_fetches_total`, `crawl_ingest_not_modified_recorded_total`, and `crawl_ingest_not_modified_refused_total` on the node, and `yacy_crawler_not_modified_refetches_total` on the crawler. None carry URL labels.

### Peer protocol

- Outbound hello, `transferRWI`, and `transferURL` POSTs are encoded as `multipart/form-data`, so large bodies are accepted by Java YaCy peers whose servlet container caps URL-encoded forms. Local row and body budgets are unchanged. A cancelled index transfer no longer tries the next endpoint.
- Peer-protocol clients refuse HTTP redirects and return the redirect status to the caller. Seedlist downloads and the crawler, admin, and web-fetch clients keep following redirects.
- The hello greeting and back-ping remember the exact endpoint at which a peer last answered directly with its own identity and try it first while the peer still advertises it. Under the HTTPS preference they also try a DNS-named peer at `https://<name>:443` before plain HTTP; IP-literal peers are not tried this way. Peer rosters written by earlier releases open unchanged.
- A peer message with `process=post` is refused unless its `iam` value equals the hash in the posted seed.
- When the direct connection comes from a configured trusted proxy, the client address is now the nearest `X-Forwarded-For` hop that is not itself a trusted proxy. A malformed entry stops the walk.
- The accepted-request debug log no longer records form names or values. It records the method, path, number of form fields, and declared body length.

### DHT handoff

- An outbound restore no longer replaces a posting written after selection, and selection no longer removes a posting that changed after it was chosen.
- Purging a live posting, including URL deletion, drops a posting waiting for transfer, so restore and restart recovery do not bring it back. A posting already sent to a peer is not recalled.

### Search

- Within one shard search, each field's term dictionary is opened once per index segment and each term's postings are read once per segment. Later readers of the same field and term reuse them, so long queries that repeat a term across clauses no longer repeat the lookup. Result documents and scores are unchanged.
- Snippet selection chooses the window of at most 320 runes that covers the most distinct matched query terms, then the shorter span, then the earlier offset. The excerpt then starts and ends at a sentence or paragraph boundary without cutting the selected matches. Overlapping Chinese, Japanese, and Korean word pieces stay whole at the window edge.

### Crawler

- Feed parsing reads RSS 2.0, RSS 1.0, Atom 1.0, and Atom 0.3 feeds in one bounded pass, takes at most 200 direct items per feed, resolves relative links against the feed address and each enclosing `xml:base`, and keeps only links from items closed before a malformed or truncated feed fails.
- HTML pages are decoded and parsed once and shared between the page parser and the browser-render decision.
- Each crawler-generated RWI posting carries field `n`, the URL component count, using the Java YaCy counting rule instead of zero.

### Security updates

- `github.com/klauspost/compress` is updated to v1.20.2 for the two-block frame panic correction (GO-2026-6865). Values stored with v0.0.75 remain readable, and v0.0.75 reads values written with this release.
- `golang.org/x/crypto` is pinned to a revision that removes the unmaintained OpenPGP packages (GO-2026-5932).
- The crawler image pins `musl` and `musl-utils` `1.2.6-r3` (CVE-2026-107891) and `zlib` `1.4-r0` (CVE-2026-85091).

## Compatibility

- YaCy wire: outbound peer POSTs change encoding from URL-encoded to multipart form data. Java YaCy and earlier yago releases accept both encodings, and this release still accepts URL-encoded bodies inbound.
- A peer that posts a message without an `iam` value matching its seed hash is refused with the existing rejection response.
- A peer-protocol endpoint that answers with a redirect is no longer followed.
- Node-crawler messages: conditional recrawl fields are additive. An older crawler ignores them and fetches unconditionally; an older node ignores the stored validators and never confirms a not-modified observation, so a current crawler fetches the page in full. Node and crawler may be upgraded in either order.
- Storage: no collection, record format, or index mapping changes require conversion. Recrawl schedules gain additive validator fields; a schedule without them is stored as before. Existing data needs no conversion.
- No setting, environment variable, listener, port, or service changes. The Compose and systemd deployment examples are unchanged.

## Upgrade and rollback

- Upgrade the node and crawler in either order. On a generic bare-metal host:
  1. Fetch the release `.deb` and verify its artifact attestation against repository `D4rk4/yago`, the release workflow, tag `v0.0.76` and its source commit.
  2. Back up `/opt/yago/data`.
  3. Stop `yago-node` and `yago-crawler`.
  4. Install with `dpkg -i`.
  5. Start both services and confirm they report healthy.
- Rolling back to v0.0.75 needs no data conversion. A v0.0.75 node ignores the stored recrawl validators and recrawls unconditionally. Rollback restores per-update commits for contended writes and per-call roster writes.

It also covers symbol-level govulncheck, race-instrumented tests, the recorded test shuffle, bounded fuzz smoke, exact 100% statement coverage in every module, and builds.

- Dockerized Trivy 0.72.0 reported no HIGH or CRITICAL vulnerability, secret or misconfiguration findings in the source tree or in either locally built product image.
- The local node and crawler images built and reported their versions. The bundled browser reported Firefox ESR 140.12.0esr.
- The crawler end-to-end suite passed all 8 tests. They include independent node-only and crawler-only restarts with new crawler sessions and continued crawl progress, and a joint restart that resumes an unfinished frontier.
- The node end-to-end suite passed all 20 tests, including the tests against a real Java YaCy peer.
- Regression tests for the storage write changes were each checked against deliberately broken code:
  - Eight queued contended writes share one commit, and 33 take two; a group limit of one failed.
  - A failing member, a swallowed storage access error, a panicking member, and an unreadable shard root each leave the other members' writes committed and return the failure only to its own caller; removing the solo rerun, the panic recovery, the access-error check, or the root-failure rerun failed.
  - A failed group commit reaches every member. A write cancelled while queued writes nothing, and a write cancelled after its group formed reports the commit; ignoring the formed group's outcome failed.
  - A repeated caller within five minutes writes nothing and refreshes its in-memory membership. An elapsed interval, a backwards clock, a changed seed, a retry cooldown, an unverified-to-verified upgrade, a new answered endpoint, and an unreadable row each still write. A junior observation writes nothing for a known peer and writes a new peer. Removing each of these conditions, or keeping statistics in the seed comparison, failed.
  - Compacted and split shards keep deferred-fsync mode both on and off; dropping either assignment failed.
- Release issue review: the only open issue labeled `bug` or `enhancement` is #3 (node memory use). It is outside this release's scope and remains open. No open `enhancement` issues exist.
- Anonymization audit: this memo, the feature catalog rows, the specification text, the commit messages, and the new tests were searched for copied operational input. They contain only synthetic documentation addresses and placeholder host names; no findings.

## Known limitations

- The write reduction from grouped commits and skipped roster writes has not yet been measured in production.
- A DHT posting already sent to a peer is not recalled by a later purge.
- The production effect of shared term postings on long-query CPU is not yet measured.
- Open issue #3 (node memory use) is not addressed by this release.
