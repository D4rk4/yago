## Abstract

Yago v0.0.77 widens the optional fetch-on-extract path behind the Tavily-compatible `/extract`, `/crawl` and `/map` endpoints. A live fetch now returns plain-text and Markdown pages verbatim and returns the embedded text of PDF documents through a PDF reader that node and crawler now share. The default per-fetch response limit rises from 2 MiB to the 4 MiB hard ceiling. PDF titles now come from the document information dictionary rather than the first title string in the file, which was often a bookmark. No storage conversion, listener, or wire-protocol change is required. Node and crawler may be upgraded in either order; rollback to v0.0.76 needs no conversion.

## Changes

### Fetch-on-extract content types

- Fetch-on-extract remains off unless the operator enables it. When enabled, a live fetch previously accepted only HTML and XHTML responses and failed every other content type.
- A `text/plain` or `text/markdown` response is now returned as its body with surrounding white space removed. It carries no title, links or images.
- An `application/pdf` response is now read for its embedded text and its document title. A PDF without readable text fails as before. A PDF carries no links or images.
- The same rules apply to the pages that `/crawl` and `/map` fetch, so those walks no longer stop at a PDF or plain-text page; such a page contributes no further links.
- Other content types still fail.

### Response limit

- The default for `YAGO_EXTRACT_FETCH_MAX_BYTES` and its admin setting changes from 2 MiB (`2097152`) to the 4 MiB hard ceiling (`4194304`). A lower configured value is still accepted, a larger one is still rejected, and an over-limit response is still refused rather than truncated.
- The Compose, systemd and `.env` examples show the new default.

### Shared PDF reader

- The crawler's PDF and PostScript text reader moved into a new standard-library-only module, `yagopdf`, which both the node and the crawler import (ADR-0088). Its text extraction, decoding limits and PostScript handling are unchanged.
- The crawler still routes PostScript by `.ps` extension or `%!PS` body and still falls back to the first text line when a PDF has no title.
- Both product images build the new module. No new third-party dependency is introduced.

### PDF title

- The reader previously used the first `/Title` string anywhere in the file. In many PDFs that string belongs to an outline (bookmark) entry, so documents were titled with a section heading.
- The title now comes from the document information dictionary named by the newest `/Info` reference in a trailer or cross-reference stream. If that dictionary has no title, or the referenced object is absent, the PDF has no title; the crawler then uses its first-line fallback. Only a file without any `/Info` reference still uses its first `/Title` string.
- Existing title length and string-size limits are unchanged.

### Tests

- A peer-membership cancellation test waited at most 100 ms for a result that a loaded test host can schedule later; it now waits up to 5 s and still fails on a hang. Runtime behavior is unchanged.

## Compatibility

- YaCy wire: unchanged.
- Tavily-compatible API: request and response shapes are unchanged. URLs that previously failed fetch-on-extract because of their content type, or because they were between 2 MiB and 4 MiB, can now return results.
- Node-crawler messages: unchanged. Node and crawler may be upgraded in either order.
- Storage: no collection, record format, or index mapping changes. Existing data needs no conversion. Previously indexed PDFs keep their stored titles until a normal recrawl replaces them.
- Settings: an explicit `YAGO_EXTRACT_FETCH_MAX_BYTES` value in the environment, or a stored runtime override, keeps its value. Only nodes relying on the default see the larger limit.
- No listener, port, or service changes.

## Upgrade and rollback

- Upgrade the node and crawler in either order. On a generic bare-metal host:
  1. Fetch the release `.deb` and verify its artifact attestation against repository `D4rk4/yago`, the release workflow, tag `v0.0.77` and its source commit.
  2. Back up `/opt/yago/data`.
  3. Stop `yago-node` and `yago-crawler`.
  4. Install with `dpkg -i`.
  5. Start both services and confirm they report healthy.
- Rolling back to v0.0.76 needs no data conversion. A v0.0.76 node returns to HTML-only fetch-on-extract with a 2 MiB default limit, and a v0.0.76 crawler returns to the first-`/Title` rule for newly crawled PDFs.

- Regression tests for the changed behavior, all on synthetic documents, assert both directions:
  - Plain-text and Markdown bodies are returned verbatim; an unsupported content type and a body one byte over the limit still fail.
  - A readable PDF returns its text and title; a PDF without readable text and a PDF one byte over the limit fail.
  - An outline `/Title` placed before the document information dictionary is not chosen; a UTF-16 title in a cross-reference stream and the newest of two trailers are chosen; a dictionary without a title and a missing referenced object yield no title; a file without an `/Info` reference keeps the first-title rule.
- A locally built node image with fetch-on-extract enabled returned the embedded text of a public vendor PDF of about 3 MB, which v0.0.76 refused. For the same document the reader now reports no PDF title instead of an outline label, because its information dictionary carries none.

## Known limitations

- PDF extraction reads embedded text only. Scanned pages and composite fonts without a usable Unicode map are not read, and no OCR is performed.
- A plain-text or Markdown body is returned as received; it is not converted from a declared non-UTF-8 character set.
- A PDF fetch holds up to 4 MiB of response and decodes within a 32 MiB per-document budget; one `/extract` request resolves at most four URLs at a time.
- Open issue #3 (node memory use) is not addressed by this release.
