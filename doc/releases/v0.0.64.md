## Abstract

Yago v0.0.64 adds shared operational search diagnostics and server-generated request correlation across the node's public, peer and operations interfaces. Diagnostic records identify bounded failure stages and causes without retaining queries, URLs, credentials or peer identities. HTTP request logs rename `duration_ms` to `durationMs`; operators must update dependent log queries. Review fixes preserve retryable crawl authorization, enforce deliverable denylist limits and canonical matching, retain remote-search incompleteness when budgets omit work, and isolate private-network allowances from caller mutation. The crawler image updates existing security-sensitive libraries. Upgrade the node and crawler together. Stored formats and wire message shapes remain compatible; no index rebuild is required.

## Changes

### Make concurrent diagnostic assertions safe

The previous unpublished attempt exposed a data race in the test log capture: a background crawler fixture could still write while a diagnostic assertion read its buffer. The corrected test fixtures synchronize capture access and end background work with the owning test. This is a test-lifecycle correction; it does not change production log content, search policy or service behavior.

### Share private operational diagnostics across node interfaces

Tavily, the public portal, YaCy-compatible search and Admin search/explain use the same search execution diagnostic. It records bounded stage/cause counts, retrieved and total result counts, and an execution-error category when present. Empty or errored incomplete execution is WARN; a usable partial result is DEBUG. Complete searches and query-shape notes without an execution error do not create this diagnostic. The existing query-logging setting need not be enabled.

A fresh server span supplies `serverSpanId` to public, peer and ops HTTP request records, search diagnostics, web-engine attempts and web-seed lifecycle records. Incoming trace IDs continue their existing propagation and exemplar behavior, while caller request IDs and incoming span IDs are not copied into these log fields. The trace parser reads the sampled flag as a bit field. Background seed work copies only the trusted server identifier, preserving its isolated timeout and cancellation behavior.

HTTP records use registered route patterns or `unmatched`; custom method tokens use `other`. The authenticated ops path now preserves its matched route through the session guard. Structured search, portal and seed records omit raw error and panic payloads, URLs and peer identifiers. Failure metadata is internal and excluded from JSON. Session merging preserves its existing Source/Reason identity while updating private diagnostic metadata.

### Preserve truthful remote-search completion

Planned jobs omitted by call or response budgets now contribute a local budget failure. Decoding exhaustion retains later completed peer errors, and local limits do not penalize a peer. Fully queried empty answers remain complete. Missing targets, missing responses and unsupported strict-safe engines have distinct bounded diagnostic causes. Existing call, concurrency and latency limits are unchanged.

### Keep transient ingest authorization retryable

Only confirmed lease loss produces `FailedPrecondition` and revokes a crawler grant. Context, storage and other operational authorization errors now use the existing negative acknowledgement and retryable `Unavailable` path. Valid lease ownership is retained during retry. No permanent data loss was established in the old path; the confirmed defect caused unnecessary suspension, recovery or re-fetch.

### Wait for startup policy connection readiness

The crawler startup policy read now waits for a temporarily unavailable gRPC connection within its existing connect timeout. Deadline expiry and caller cancellation still fail startup, and the older-node `Unimplemented` fallback remains unchanged. This removes an immediate startup failure observed before sitemap processing during the container integration gate; no sitemap parser change or timeout increase is introduced.

### Enforce one deliverable denylist policy

Exact URL rules now match equivalent shared canonical URL spellings in served results and crawler admission. Raw persisted aliases remain visible and individually removable; removing one alias retains any remaining rule for that resource. Values outside HTTP(S) canonicalization retain literal matching, and domain suffix rules are unchanged.

Additions validate raw and canonical policy bounds atomically before durable or visible state changes: at most 4,096 retained rules, 1 MiB of encoded policy, and the existing per-entry encoding and size limits. Duplicate refresh at a valid limit remains supported. Legacy oversized or malformed policy rows are retained for operator removal. The crawler verifies the original wire revision before compiling canonical lookups; revision hashing and message fields are unchanged.

### Isolate egress allowances and update the container baseline

Private-CIDR options copy their input when constructed. Mutating a caller-owned slice afterward cannot change an existing guard or another guard built from the same option. The default private-network restrictions and reserved-range protections remain in force.

The crawler image pins its existing PCRE2 runtime library to Alpine `10.49-r0`, addressing CVE-2026-103111. [PCRE2 10.49](https://github.com/PCRE2Project/pcre2/releases/tag/pcre2-10.49) corrects an out-of-bounds write under specific JIT stack conditions; project-specific exploitation was not established. The existing OpenSSL package pins advance to `3.5.9-r0` because the former exact revisions are no longer available from the configured Alpine indexes. The complete pinned package set resolves for both release architectures. The base digest and other package pins remain unchanged.

## Compatibility

- Tavily request/response shapes, YaCy wire shapes and node-crawler message fields remain compatible. The existing incomplete-zero status policy is unchanged; newly reported budget omissions can now expose an incomplete search where an earlier version returned an unjustified empty success.
- HTTP log consumers must replace `duration_ms` with `durationMs`. New correlation and diagnostic fields use camelCase.
- Ops HTTP requests now contribute to the same request metrics and logs as the other node listeners. Redirects outside instrumentation remain outside those observations.
- Valid trace flags preserve their sampled bit even when additional flag bits are set. Existing latency exemplars remain supported.
- Denylist matching now recognizes canonical aliases; raw rows and wire revision hashing remain compatible. No stored-format migration or index rebuild is needed.
- No Go module dependency, service, image repository, listener or environment setting is added. Existing query logging, web fallback and crawler-seeding operator controls remain in effect.
- The reusable-module API gate compares against the exact published v0.0.62 tag and commit. No reusable-module exported signature changes are introduced.

## Upgrade and rollback

Use matching node and crawler binaries from the published package. Verify the package's GitHub-hosted attestation against this repository, release workflow, immutable tag ref and source commit. Preserve existing configuration and data. Follow the stopped two-service backup procedure for generic hosts, install with `dpkg`, then start and verify the node before starting the crawler. The package enables services but does not automatically start them.

Where an established target-specific operator policy skips a new pre-upgrade backup, preserve all existing archives unchanged. Stage the verified package under its versioned release directory and retain the same node-before-crawler startup order.

Review legacy denylist rows if policy delivery reports a contract limit or encoding failure; remove or correct offending rules through the operator surface before crawler policy delivery can resume. This release does not silently prune rules. Update log queries for the duration-field rename.

Rollback requires stopping both services and reinstalling the previous verified matching package. No storage migration is introduced, but rollback restores the older diagnostics, canonical-rule gap, authorization classification, egress option aliasing, missing budget-omission evidence and immediate startup failure on a transient policy-connection refusal. Older container images also restore the previous vulnerable PCRE2 package. Host browser/library updates on bare metal remain the operating system's responsibility.

## Known limitations

- This release adds diagnosis and fixes the identified boundary defects; it does not guarantee that every search source will answer or that every query will return results. Provider and peer availability remain external factors.
- Existing historical crawler/gRPC log redaction was explicitly outside this logging change. The privacy guarantee here covers the new shared node diagnostics and the touched structured search/seed records, not the Go runtime's default crash output or an operator-enabled full query log.
- Malformed or oversized legacy denylist rows are preserved for removal; no automatic policy deletion is performed.
- Open issue #3, concerning memory usage, remains open. Its unchanged historical evidence does not establish a current reproducible defect or justify a memory-policy change in this candidate. No issue carrying the exact `enhancement` label was open at the reviewed release scope.
