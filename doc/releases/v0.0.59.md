## Abstract

Yago v0.0.59 bounds selective multi-term retrieval by complete lexical requirements so common individual terms cannot force avoidable exhaustive reads. It also makes the release gate block on pinned gosec, NilAway, apidiff, govulncheck, race detection, deterministic test shuffling, and bounded active fuzzing. NilAway diagnostics now use explicit plain full-path output, independent of runner terminal settings. Public engineering artifacts contain neutral evidence instead of copied operational input. Immutable v0.0.57 and v0.0.58 remain unpublished attempt history. Runtime APIs, wire and storage formats, settings, runtime dependencies, and service topology are unchanged. Upgrade from v0.0.56 requires neither migration nor index rebuild.

## Changes

### Bound multi-term candidate retrieval

An anonymous production search could return an incomplete zero-row response on its first request and local rows on an immediate repeat. The node remained ready and neither service recorded a restart, memory-pressure event, or OOM event. Provider-only and direct outbound synthetics returned rows within their own budgets, isolating the defect to local deadline composition rather than an honest corpus or provider miss.

The disk candidate query formerly admitted the union of every individual positive term across eligible analyzers. One common term could therefore reach the 4,097th identity sentinel and select exhaustive analyzer-scoped retrieval even when the complete multi-term requirement was selective. The candidate is now the disjunction of complete analyzer-specific requirement branches. Strict and fuzzy branches require every retained term; relaxed branches use the same minimum-term requirement as the authoritative final query. Stopword removal remains branch-local, dictionary alternatives remain independent, and exclusions, filters, scoring, ordering, pagination, and final result identity remain owned by the unchanged final query.

Each child still examines at most 4,097 identities. At most 4,096 complete candidates become an internal zero-score filter; the sentinel retains exhaustive retrieval instead of truncating possible results. At the outer hard deadline, a result already queued for delivery is returned while unfinished work receives no additional time. Tests admit all qualifying strict, relaxed, fuzzy, and analyzer-specific candidates and reject every below-requirement candidate. Existing equivalence tests retain final result identity, order, score, total, filters, expansion behavior, and honest empty answers.

ADR-0078 and FTR-203 record this boundary. A disposable four-processor diagnostic against an isolated copy of the derived search index returned the corrected request on its first read. All 100 synchronized, queue-inclusive backend reads returned hits inside the 1.8-second context, with p99 below 733 milliseconds. This validates the changed Bleve candidate boundary on that isolated copy; it is not a full HTTP or production-capacity claim.

### Keep operational input private

Current tracked release material, ADRs, feature records, and search fixtures use neutral synthetic descriptions. The workspace policy classifies prompts, queries, submitted URLs, payloads, corpus excerpts, identifiers, credentials, and privately supplied reporter material as non-public operational input unless publication is explicitly authorized. A copied-input audit is required before a tag or public issue reply. The immutable v0.0.57 tag was not moved, deleted, or reused.

### Add complementary code-quality release gates

`make verify` now directly requires standalone gosec v2.28.0, the Go race detector, NilAway at exact module commit `8649a03c818a`, apidiff at exact `golang.org/x/exp` commit `e88cd73687aa`, govulncheck v1.7.0, a recorded uncached test shuffle, and active discovery-driven fuzz smoke. Build-time tools are version-pinned and installed under `.toolchain`; embedded Go module identities are verified for source-installed commands.

Gosec runs across all six production modules. Its reviewed exceptions are exact file-and-rule pairs, with no repository or directory suppression. NilAway runs separately for each production module, excludes test files, and compares the complete finding set with an exact sorted 82-location debt baseline. A new, removed, moved, or unclassified finding fails the gate. The command explicitly disables ANSI pretty printing and requests full file paths before parsing, so CI terminal settings cannot change baseline identity. Policy tests simulate both terminal-dependent colored output and shortened paths and prove that removing either format flag is refused.

Apidiff compares the four reusable modules with exact published v0.0.56 commit `b7472e93de54309a6da36ef307ff9140952ba950`; it also refuses a moved tag, a non-ancestor baseline, or an incompatible API result. Govulncheck performs symbol-level analysis in all six modules and fails on a reachable advisory or analysis/database error. Every module receives one uncached shuffle using seed `20260831`. The fuzz gate discovers every named fuzz target and runs each for five seconds with one worker; it refuses zero targets, an invalid name, a failed target, or a configured duration outside one through 30 seconds.

ADR-0079 through ADR-0083 and FTR-204 record the dependencies, ownership boundaries, limitations, and bidirectional policy tests. The CI cache now covers the actual `.toolchain/bin` directory and invalidates on runner architecture, module sums, tool locks, or installers.

## Upgrade and rollback

1. Wait for the immutable v0.0.59 workflow to pass every build, scan, attestation, public-registry, and anonymous exact-tag check.
2. Download the architecture-matching Debian package and verify its GitHub artifact attestation against repository `D4rk4/yago`, `.github/workflows/release.yml`, `refs/tags/v0.0.59`, and the tagged source commit.
3. Follow the target data-protection policy. Generic bare-metal nodes take a coordinated stopped backup. The documented yagoseek.dev exception creates no new backup and preserves every existing archive under `/opt/yago/backups`; stage the verified package under `/opt/yago/releases`.
4. Stop `yago-crawler` and `yago-node`, install the package with `dpkg -i`, and confirm that package installation left both services inactive.
5. Start and verify `yago-node` first: exact identity, health, readiness, indexed document total, listeners, stable restart count, bounded logs, resource counters, and first-request multi-term acceptance.
6. Start `yago-crawler` only after node acceptance. Confirm a Connected broker state, a new logical session, crawl progress, and no repeating lease-loss or reconnect loop.

For rollback, stop both services, install the exact published v0.0.56 package, and start the node before the crawler. No format conversion or index rebuild is expected.

## Known limitations

- The isolated 100-request result covers the native search backend and copied derived index, not the complete HTTP path or production-host capacity. Sustained hundreds-request service still requires separately implemented and measured horizontal read capacity with independent CPU and I/O, independently owned immutable generations, bounded admission, freshness-aware routing, queue-inclusive latency evidence, and one-replica-loss capacity. Multiple processes must not share one mutable Scorch directory.
- DDGS can be throttled, can change its markup, and can return an honest empty result. It remains disabled unless an administrator enables the applicable mode.
- Gosec and NilAway are approximate static analyzers. Apidiff cannot detect behavioral incompatibility. Govulncheck depends on curated advisories and static reachability. Race detection observes only executed paths and interleavings; one shuffle and a five-second fuzz smoke do not replace sustained order exploration or fuzzing.
- The NilAway baseline is explicit debt, not proof that every retained location is safe. It must shrink through reviewed code changes rather than speculative defensive branches.
- Issue #3 remains open because a point-in-time resident-memory reading does not establish growth or pressure. Repeated memory-class and cgroup evidence is required before attributing a defect.
